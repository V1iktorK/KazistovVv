## Что это

**KazistovVv** — инженерная среда для промышленных манипуляторов, выполненная как
приложение Unity. Это не просмотрщик CAD и не средство воспроизведения записей: это
полный операторский цикл — **прицелиться, спланировать, посмотреть, проверить, выполнить** —
с допуском безопасности перед каждым движением.

| Что | Как это реализовано |
|---|---|
| **Роботы** | Ровно два на сцену: **6-осевой манипулятор** (`Робот_6ос_Стенд1`, `SixAxisController`) и **SCARA** (`SCARA_Стенд2`, `SCARAController`, оси J1 / J2 / Z-призматическая) |
| **Движение** | Планировщик RRT / двунаправленный RRT, время-оптимальная перепараметризация, исполнение по S-профилю, планирование с ограничениями, сглаживание пути, энергооптимальные варианты |
| **Проверка** | Прямая и обратная кинематика (CCD + якобиан), лимиты суставов, зоны сингулярности, самоколлизии, мир коллизий на капсульных цепочках, зоны запрета, динамические препятствия |
| **Безопасность** | Единственная точка входа любого движения (`MotionExecutor`) за `SafetyGate`; проверки перед пуском, имитация отказов, монитор состояния, манекены людей в рабочей зоне |
| **Интерфейс** | Десктопный интерфейс в духе **FreeCAD**, на uGUI, **собирается кодом в рантайме** — строка меню, тулбар-иконки, док-панели, дерево моделей, свойства, статус-бар |
| **XR** | Ветки десктопа, **VR**, **MR** и **AR**: XR Interaction Toolkit 3.5.1, OpenXR, Meta XR, AR Foundation 6.5.0; проверено на шлемах **PICO 4 Ultra** и Meta Quest |
| **Обмен данными** | Экспорт в **KRL** (KUKA), **KAREL** (FANUC), **RAPID** (ABB); импорт **URDF** и **STEP** |
| **Анализ** | Метрики траектории (время, длина, энергия), тепловые карты, карты усилий, графики по суставам, отчёты PDF, скриншоты и запись видео |
| **Производственные функции** | Запись и воспроизведение траекторий и поз, журнал действий, отмена и повтор, мастер калибровки TCP, калькулятор нагрузки, гриппер, виртуальный пульт, менеджеры сценариев и сессий, совместная работа по UDP, веб-дашборд |
| **ИИ в рантайме** | **Отсутствует.** Ни LLM, ни нейросеть в движении не участвуют. Конвейер — детерминированная кинематика, проверка коллизий и планирование |

Проект намеренно сделан **детерминированным и проверяемым**: любое решение о движении
восстанавливается по журналу действий, и между оператором и роботом нет генеративной модели.

## Как работает оператор

Поток — это конечный автомат под управлением `TrajectoryFlowController`:

```
Idle
  └─ красный лазер (Z) + ЛКМ по поверхности ────▶ PointSelected
        └─ идёт планирование ──────────────────▶ TrajectoriesShown  (8 вариантов = 8 фантомов)
              └─ зелёный лазер (X) + ЛКМ по траектории ▶ PhantomsMoving
                    └─ зелёный лазер + ЛКМ по фантому ──▶ RobotMoving ──FinishMotion──▶ Idle
  Enter ──▶ PointMoveMode   (Q/E, W/S, A/D двигают точку; Enter подтверждает, Esc отменяет)
  Esc   ──▶ ResetAll ──▶ Idle
```

Ни одно движение не выполняется в обход допуска безопасности, а исполнитель движения —
единственная точка входа для перемещения во всём коде.

## Возможности

<details>
<summary><b>Планирование и движение</b></summary>

- Планировщик RRT / BiRRT со время-оптимальной перепараметризацией
- Планирование с ограничениями, ограничения на путевые точки, сглаживание пути
- Энергооптимальный и время-оптимальный варианты со стендом сравнения
- Зоны сингулярности, зоны запрета, динамические препятствия, оптимизация коллизий
- Исполнение плана во времени, визуализация трубки траектории, метрики плана

</details>

<details>
<summary><b>Робот, оснастка и калибровка</b></summary>

- Параметры Денавита–Хартенберга, прямая кинематика, обратная задача (CCD), якобиан
- Автоопределение суставов робота, поставленного в сцену (`SixAxisAutoSetup`)
- Гриппер, кинематика инструмента, мастер калибровки TCP, калькулятор нагрузки
- Библиотека поз и выбор позы

</details>

<details>
<summary><b>Безопасность и проверка</b></summary>

- Единственная точка входа движения (`MotionExecutor`) под защитой `SafetyGate`
- Проверка лимитов суставов, скоростей и зон до выдачи любого импульса
- Имитация отказов и проверка перед пуском, монитор состояния
- Манекены людей в рабочей зоне для проверки достижимости и зазоров

</details>

<details>
<summary><b>Интерфейс и производство материалов</b></summary>

- Десктопный интерфейс, собираемый в рантайме: докинг, темы, полная навигация с клавиатуры
- Работа с несколькими камерами, «картинка в картинке», кинематография, студия сцены (окружение / свет / материалы)
- Скриншоты, запись видео через Unity Recorder, отчёты PDF
- Тепловые карты, карты усилий, графики по суставам
- Виртуальный пульт, быстрый старт, обучение, режим презентации
- **7 языков интерфейса** из коробки: русский, английский, немецкий, испанский, французский, японский, китайский

</details>

<details>
<summary><b>XR-слой</b></summary>

- Ветки оператора для десктопа, VR, MR и AR за единой абстракцией ввода
- OpenXR со слоем Meta X API; поддержка рантайма PICO для PICO 4 Ultra
- Сервисы ввода: трекинг рук, взгляд, голос, фовеальный рендеринг
- Тактильная отдача и пространственный звук
- Пространственные якоря и инструменты калибровки для постановки робота на реальный стол

</details>

## Сборка и запуск

### Требования

| Требование | Значение |
|---|---|
| Unity | **6000.5.6f1** (Unity 6). Более старые редакторы проект не откроют — код использует find-API Unity 6 |
| Конвейеры рендера | Нужны **оба**: **URP 17.5.0** (глобальное умолчание, Android / шлем) **и HDRP 17.5.0** (уровень качества «PC») |
| Windows | Windows x86-64 с Windows Build Support (IL2CPP) |
| Android | Android Build Support, минимальный SDK 32, целевой 34 |
| XR | Лоадер OpenXR + слой Meta X; рантайм PICO для PICO 4 Ultra |
| Первый импорт | 5–15 минут, пока строится `Library` (шейдеры HDRP импортируются долго) |

### Открытие

1. Unity Hub → **Add** → выбрать папку, внутри которой лежат `Assets`, `Packages`, `ProjectSettings`.
2. Дождаться окончания импорта.
3. Открыть **`Assets/_Project/00_Scenes/MainScene.unity`**.
4. Признак здорового старта: в консоли появляются строки `[RobotInventory] Роботов в сцене: 2 …`
   и баннер интерфейса, а в Hierarchy создаётся объект `KazistovVv_UI`.

### Настройки плеера, которые полезно знать

| Параметр | Значение |
|---|---|
| `productName` | `KazistovVv` |
| `bundleVersion` | `0.1.0` |
| `applicationIdentifier` | `com.KazistovVv.app` |
| Цветовое пространство | Linear |
| Обработка ввода | **Both** (старый `Input` и новый Input System работают одновременно) |
| Сцена в сборке | только `MainScene` |

Пошаговая инструкция, включая сборку APK и проверку идентификатора, —
в [`Docs/DEVELOPER_README.md`](Docs/DEVELOPER_README.md).

## Тесты и CI

| Набор | Что покрывает |
|---|---|
| **EditMode** | около **1 300** тестов в 122 файлах — планирование, кинематика, безопасность, интерфейс, конвейер рендера, локализация |
| **PlayMode** | полный сценарий робота на настоящей сцене |
| **E2E** | панель настроек и переключатель VR/MR через настоящий uGUI |
| **Гигиена репозитория** | артефакты сборки в индексе, посторонние файлы внутри `Assets`, `.meta` без ассета, не-ASCII в путях, ключи подписи в git |

CI работает на GitHub Actions: [`.github/workflows/unity-tests.yml`](.github/workflows/unity-tests.yml)
на каждой ветке и в pull request, и [`.github/workflows/nightly.yml`](.github/workflows/nightly.yml)
для глубокого ночного прогона (PlayMode, E2E, сборка APK). Конвейер прямо говорит о том, что
проверить **не удалось**: job, который не может выполниться, падает явно, а не притворяется успешным.
