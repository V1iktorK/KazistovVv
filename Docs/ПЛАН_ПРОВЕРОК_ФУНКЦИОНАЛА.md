# ПЛАН ПРОВЕРОК ФУНКЦИОНАЛА (кроме столов)

Задача: проверить **весь** существующий функционал, а не только постановку на стол. Ниже — перечень
с пометкой, КАКИМ ИЗМЕРЕНИЕМ проверяется каждый пункт. Правило прежнее: пункт считается проверенным
только тогда, когда есть машинное доказательство (тест, строка журнала с числами, файл), а не
«посмотрел глазами».

Обозначения: **[Г]** — добавляется в приёмочный гейт как отдельная проверка; **[Т]** — покрывается
тестами EditMode/Е2Е; **[Ж]** — доказательство берётся из журнала устройства.

---

## A. Сохранение и восстановление состояния

| № | Что проверяем | Как докажем |
|---|---|---|
| A1 | Настройки переживают перезапуск приложения (режим VR/MR, язык, комфорт, единицы) | **[Ж]** выставить значения → `am force-stop` → запуск → строка «настройки после рестарта: …» с числами |
| A2 | «Сброс настроек» действительно сбрасывает всё, и только настройки | **[Т]** снимок всех значений до/после; постороннее состояние не тронуто |
| A3 | Испорченный файл настроек не мешает запуску | **[Т]** мусор/обрезанная запись → умолчания + честное сообщение, без исключения |

## Б. Языки и текст

| № | Что проверяем | Как докажем |
|---|---|---|
| Б1 | Переключение языка реально меняет подписи во всех 7 языках | **[Т]** для каждого языка: подпись до ≠ подпись после, и она непустая |
| Б2 | Нет языков «с нулём строк», которые нельзя выбрать | **[Г]** в списке нет языка с 0 строк (сейчас проверяется в Е2Е; вынести в гейт) |
| Б3 | Длинные переводы не выходят за панель и не обрезаются молча | **[Т]** замер ширины текста против ширины контейнера для каждого языка |
| Б4 | Паритет ключей: нет пропущенных и лишних строк | **[Т]** сравнение наборов ключей всех словарей с эталоном |

## В. Запись и воспроизведение

| № | Что проверяем | Как докажем |
|---|---|---|
| В1 | Запись стартует и файл реально растёт | **[Ж]** размер файла до/после, прирост > 0 |
| В2 | Стоп закрывает файл; повторная запись не затирает предыдущую молча | **[Т]** два файла, оба читаются |
| В3 | Воспроизведение соответствует записанному | **[Т]** метрика расхождения по траектории ниже порога |
| В4 | Экспорт: путь, размер, содержимое | **[Т]** файл создан, размер > 0, содержимое парсится |

## Г. Движение и безопасность

| № | Что проверяем | Как докажем |
|---|---|---|
| Г1 | Пауза и продолжение не превращаются в аварию (закрыто 12.11) | **[Т]** уже есть: `KvPauseSafetyTests` |
| Г2 | Спам-нажатия (10 раз за 0,2 с) не ломают состояние | **[Т]** состояние после спама = состояние после одного нажатия |
| Г3 | Замерший поток данных останавливает движение (watchdog) | **[Т]** есть; усилить границей по времени |
| Г4 | Откат при самостолкновении не выходит за буфер | **[Т]** есть в `KvP1FixTests`; проверить границы |

## Д. Ввод

| № | Что проверяем | Как докажем |
|---|---|---|
| Д1 | Клавиатурная навигация: Tab/Enter/Esc не теряют фокус, Esc закрывает | **[Т]** обход панели только клавишами, фокус всегда на существующем элементе |
| Д2 | Нет конфликтов горячих клавиш | **[Т]** регистрация клавиш уникальна (уже есть); расширить на новые панели |
| Д3 | Нет источника ввода (нет рук/гейза) → честное «нет данных» | **[Т]** без провайдера — сообщение, а не тишина |

## Е. Устойчивость среды

| № | Что проверяем | Как докажем |
|---|---|---|
| Е1 | Отказ разрешения камеры в AR не вешает приложение | **[Ж]** отозвать разрешение → запуск → строка «камера не разрешена, что делать» |
| Е2 | Потеря и восстановление трекинга не разваливают сцену | **[Т]** состояние панелей и объектов до/после потери |
| Е3 | Нет места на диске / каталог только для чтения: запись не падает молча | **[Т]** подмена пути на недоступный → честная ошибка |
| Е4 | Поворот экрана и смена размера окна (планшет) не выносят панели за экран | **[Ж]** замер координат панели до/после поворота |

## Ж. Производительность и журнал

| № | Что проверяем | Как докажем |
|---|---|---|
| Ж1 | Бюджет кадра в каждом режиме | **[Ж]** среднее и 99-й перцентиль по журналу, порог объявлен |
| Ж2 | Память не растёт на 60 с работы | **[Ж]** два замера, прирост ниже порога |
| Ж3 | Журнал не спамит (не сам тормозит приложение) | **[Ж]** строк в секунду ниже порога |

## З. Данные и сцены

| № | Что проверяем | Как докажем |
|---|---|---|
| З1 | Все сцены APK открываются и в правильном режиме | **[Ж]** три запуска, в журнале имя сцены и режим |
| З2 | Каталог роботов: каждый элемент реально загружается | **[Т]** обход каталога, все модели непустые |
| З3 | Повторный запуск после аварийного завершения не блокируется | **[Ж]** `am force-stop` в середине работы → запуск → приложение работает |

---

## Порядок работы

1. Сначала — то, что закрывает требование владельца «каждая кнопка работает»: самопрогон UI в трёх
   режимах (ВР/МР/АР) как проверка гейта.
2. Затем — блоки **А** (переживание рестарта), **Б** (языки), **В** (запись), **Г** (спам и границы):
   они дешевле всего в автоматизации и чаще всего ломаются при изменениях.
3. Потом — **Е** и **Ж** (среда и производительность): они требуют устройств и времени, но дают
   доказательства, которые нельзя получить в редакторе.
4. Пункты, которые нельзя доказать машинно (например, «в шлеме текст читается»), честно остаются
   за человеком и не закрашиваются зелёным.
