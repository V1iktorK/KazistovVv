## 2. НАЙДЕННЫЙ ДЕФЕКТ: ДВОЙНОЕ ПРИМЕНЕНИЕ РИГА

### Симптомы (со слов владельца, дословно)

> «камера перевёрнута и не поворачивается вместе с головой»
> «всё колбасит, картинка не стабильная»
> «меню далеко»

### Доказательства из журнала

```
[KvXr] Камера следует за головой: поза (-0.41, 0.92, 0.32) · высота 0,92 м
                                        ^^^^^^ глаза должны быть на 1,60 м

[KvXr] проба ориентации: курс шлема 0.0° · панель от глаз 1.15 м
[KvXr] проба ориентации: курс шлема 192.6° · панель от глаз 3.65 м
[KvXr] проба ориентации: курс шлема 185.3° · панель от глаз 48.73 м
[KvXr] проба ориентации: курс шлема 96.5° · панель от глаз 52.30 м
[KvXr] проба ориентации: курс шлема 5.7° · панель от глаз 52.44 м
[KvXr] проба ориентации: курс шлема 277.4° · панель от глаз 52.48 м
```

Курс прыгает сам по себе на сотни градусов, расстояние до неподвижной панели растёт до 52 м.
**При этом кадры идеальные** — 90 из 90. Значит дело не в производительности и не в трекинге.

### Причина

`KvXrInputSource.TryPose` уже переводит позу в **мировые** координаты:

```csharp
private static void ToWorld(ref Vector3 position, ref Quaternion rotation)
{
    if (TrackingOrigin == null) return;
    position = TrackingOrigin.TransformPoint(position);      // ← риг применён ЗДЕСЬ
    rotation = TrackingOrigin.rotation * rotation;
}
```

А `TrackingOrigin` — это риг, **внутри которого лежит сама камера**. Затем `KvXrHeadTracking`
писал эту мировую позу в локальный трансформ камеры:

```csharp
headCamera.transform.SetPositionAndRotation(position, rotation);   // ← риг применён ВТОРОЙ раз
```

### Почему не проявлялось раньше

Пока риг стоял в нуле с единичным поворотом, двойное применение совпадало с одинарным. Но риг
**двигают и поворачивают** (`KvXrLocomotion`: телепорт, поворот стиком) — и тогда ошибка
накапливается.

### Исправление

Мировая поза переводится в локальные координаты родителя камеры перед записью — как делает
стандартный `TrackedPoseDriver`:

```csharp
Transform parent = headCamera.transform.parent;
if (parent != null)
{
    position = parent.InverseTransformPoint(position);
    rotation = Quaternion.Inverse(parent.rotation) * rotation;
}
headCamera.transform.SetPositionAndRotation(position, rotation);
```

**Файл:** `Assets/_Project/01_Scripts/Xr/KvXrHeadTracking.cs`
**Коммит:** `5455484`
**Состояние:** исправлено в коде, **на устройстве ещё не проверено** (идёт сборка).

## 3. ПРОВЕРЕНО И ПРИЗНАНО НЕ ДЕФЕКТОМ

### «ЗОНЫ: причина скрытия «робот не привязан»» — каждый кадр

Выглядело как дефект: зоны достижимости не строятся. Разбор показал обратное.

**Кто печатает:** `KvXrFlowBridge.LogZones()`, строка 217:
```csharp
bool robotBound = flow != null && flow.Robot != null;
```

**Почему пусто:** `flow.Robot` заполняется внутри `TrajectoryFlowController.UpdateAim(...)`, а
`LogZones()` вызывается в `Update()` моста. На **самых первых кадрах** `UpdateAim` ещё не
отработал — робот `null`, и диагностика честно это сообщает.

**Почему это не дефект:** `ResolveSelectedRobot` возвращает `null` только если роботов в сцене
НЕТ ВООБЩЕ. В журнале `Роботов в сцене: 2` — значит привязка произойдёт на первом же кадре с
рабочим лучом.

**Что осталось непонятным:** в снятом журнале строка «ЗОНЫ: видимо 1 · причина скрытия «видно»»
не встретилась ни разу, то есть за минуту наблюдения привязка так и не отработала. Причина
может быть в том, что луч бьёт в пустоту (aimPoint в 8 метрах от оператора, роботов там нет) —
но это **гипотеза, а не доказательство**. Проверять после исправления камеры: возможно, дело
было именно в ней.

### «Панель уезжает на 52 метра»

Тоже следствие, а не отдельный дефект. `PlacePanel()` вызывается каждый кадр, когда поза руки
доступна, и ставит панель к ладони. Расстояние «от глаз» считалось от **сломанной** камеры —
отсюда и 52 метра.

**Проверять после исправления камеры.** Если панель всё равно уедет — тогда это отдельный дефект.

2. Поставить на шлем.

| Что | Должно быть | Где смотреть |

| Курс при повороте головы | меняется **плавно**, без скачков на 180° | «проба ориентации» |
| Кадры | 90/90, ≤ 11,1 мс | `PxrMetric` |

4. Если числа верные — проверить MR (следующий шаг плана).
