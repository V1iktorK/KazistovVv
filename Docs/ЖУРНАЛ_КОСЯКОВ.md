## 13.11.2026

1. **Ложный вердикт «приложение убивает система MIUI».** Самопрогон AR объявлен «обрывом на 91-м
   элементе», сделан вывод про убийство по памяти. Факт: прогон ЗАВЕРШАЛСЯ УСПЕШНО (файл отчёта
   на устройстве содержал «ИТОГ … успешно»), обрывался logcat-хвост судьи при штатном выходе.
   Причина: судья смотрел только logcat, файл отчёта на устройстве не читал.
   Исправлено: скрипт-судья читает файл отчёта с устройства при отсутствии итога в logcat.
   **Урок: различать «прогон оборван» и «приложение убито»; подтверждать гибель процесса фактами
   (последняя строка press=, состояние процесса), а не по косвенным признакам.**

2. **Дважды ложное «правка не легла» от верификатора мутаций** (KvLocalization.cs, затем
   KvUiSweepRuntime.cs; причина — битый путь «Documentос» в предупреждении). Оба раза `git diff`
   показывал, что правки на месте. **Урок: всегда сверять git diff/grep до приёмки и до отказа —
   верификатору верить нельзя ни в одну сторону (уже записано в навыке, но косяк повторился
   как минимум в восприятии — проверять молча, без выводов в отчёт до сверки).**

3. **Файлы в Telegram не дошли дважды.** `hermes send -f file` отправляет только ТЕКСТОВОЕ тело;
   вложения идут через `MEDIA:` в тексте сообщения. Владелец дважды писал «их там нет».
   Исправлено: отправка через `MEDIA:` в тексте. **Урок: вложения Telegram — только MEDIA:; проверять
   доставку вложений по факту (спросить/подтвердить), а не по строке «sent».**

4. **Не понял однословное сообщение «Написал»**, уточнение ушло в таймаут. **Урок: на короткие
   неоднозначные сообщения — сразу предлагать контекст/варианты и параллельно искать антецедент
   в истории, не зависеть от одного вопроса.**

5. **Прогон AR оборван по бюджету (313 из 504).** Полный обход (после снятия лимита MaxElements)
   не влезал в 600 с; таймаут скрипта тоже был недооценён. Исправлено: бюджет 1800 с, таймаут 1900.
   **Урок: при изменении объёма работы пересчитывать бюджеты, а не полагаться на старые числа.**

6. **«Проверено 140 из 140» ≠ полный интерфейс.** Самопрогон годами обрезал инвентарь лимитом
   MaxElements=140, а в интерфейсе ~660 кнопок — покрытие выглядело полным, а было ~21%.
   Обнаружено только глубоким разбором по коду. **Урок: покрытие сверять с инвентарём по коду,
   «зелёный прогон» сам по себе ничего не доказывает.**

7. **Задача глубокого разбора команд упала (сбой провайдера) после ~2.3 часов** — время потеряно,
   перезапущена вручную только по итогам уведомления. **Урок: критичные задачи — ставить
   страховочный контроль и перезапуск сразу, не откладывая.**

8. **DSH: перезапуск без снятия старого слушателя → EADDRINUSE**; `taskkill //PID` в bash не работает
   (нужен `cmd //c "taskkill /PID …"` или `Stop-Process`). **Урок: перед стартом сервера на фиксированном
   порту — всегда снимать старый слушатель; убивать процессы через Stop-Process.**

9. **Опечатка в пути «Documentос» (латиница/кириллица вперемешку) в команде приёмки** — `cd` по
   битому пути упал, приёмочный прогон не стартовал (exit 127). Та же кириллическо-латинская
   путаница «Documentос» дважды всплывала в предупреждениях верификатора. **Урок: пути набирать
   только копированием из проверенного источника или строить программно; не ручной ввод кириллицы
   в латинских сегментах. **ПОВТОРИЛСЯ ещё дважды в тот же час (установка APK, и тут же — правка
   этого самого журнала по битому пути). Правило не устоялось: любой путь в команде брать ТОЛЬКО
   копированием из вывода инструментов или строить программно (os.path.join/переменная).
   **Четвёртый раз — уже в параметре workdir фонового запуска (прогон шлема молча не стартовал).
   Итоговое правило: и cd, и workdir, и аргументы — через glob-шаблон или переменную из вывода
   инструмента; ручной ввод пути = автоматический косяк.******

11. **Презентация не дошла в ТГ: в строке `MEDIA:` был неверный диск** (`D:/Users/...` вместо
    `C:/Users/...`), отправка молча не состоялась. Вложения подтверждать доставкой: путь строить
    программно (ls/cygpath), а не набирать. **Урок: перед `MEDIA:` проверять существование файла
    по именно тому пути, который пишется в сообщение.**

10. **v1 «КОНСПЕКТ КНОПОК» содержал 20+ содержательных ошибок** (группы вместо поштучного описания,
   «Файл пустой» при 18 пунктах, «5 словарей» при 7 и т.д.) — владелец сказал «ты не понял».
   Причина: каталог составлялся по замерам самопрогона без сверки с кодом. **Урок: каталоги и отчёты
   по интерфейсу строить ПО КОДУ (обработчики file:строка), замеры — как доказательство, а не как
   источник истины.**
