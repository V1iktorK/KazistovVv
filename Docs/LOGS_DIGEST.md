### 6.2 Три ловушки чтения этих логов

1. **`adb logcat -d` теряет начало.** Кольцевой буфер проворачивается, и строки Unity начинаются
   позже старта процесса. Именно так в §31 «потерялся» список расширений XR. Для разбора запуска
   писать журнал потоком (`Tools\_stage_a\device-stream-log.ps1`) ДО запуска приложения.
2. **Снимок экрана VR пуст.** `adb exec-out screencap -p` отдаёт чёрный кадр: VR рисуется прямо в
   композитор. Визуальная приёмка — только глазами владельца в шлеме.
3. **Приложение останавливается, когда шлем не надет** (`APP_CMD_STOP`, датчик присутствия).
   Нажатие HOME уводит в фон и обнуляет проверку ввода.

### 7.1 Новые ловушки чтения журнала §37

1. **Предупреждения пакета PICO SDK — не наши.** После установки `com.unity.xr.hands` сборки пакета
   пересобрались, и гейт впервые показал 126 `warning CS` — все из `_packages\PICO-Unity-OpenXR-SDK`.
   В нашем коде предупреждений 0. Считать «предупреждениями проекта» их нельзя, и наоборот —
   выдавать 126 за «0 предупреждений» тоже нельзя.
2. **Строка `ПОДСТРОЙКА` печатается только при ИЗМЕНЕНИИ файла.** Если её нет — сначала проверить,
   что файл вообще долетел: `adb shell ls -l /storage/emulated/0/Android/data/com.KazistovVv.app/files/`.
3. **Кисти и контроллеры одновременно не видны.** С контроллерами в руках рантайм отдаёт
   контроллеры, а не кисти: для проверки кистей контроллеры надо ПОЛОЖИТЬ (это и записано в чек-листе).
4. **`ИКОНКИ КОНТРОЛЛЕРОВ: показано 0` при живых контроллерах** означает «позы нет», а не «модель
   сломалась»: смотреть рядом строку `поза` и строку `КОНТРОЛЛЕРЫ ПОЯВИЛИСЬ`.
