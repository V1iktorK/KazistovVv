## ЧАСТЬ 0. ЧТО БЫЛО ДО СЕССИИ (не переоткрывать)

Каркас MR в проекте был, но **не работал**. Проверено чтением кода:

| Что | Состояние ДО | Почему не работало |
|---|---|---|
| Проба сквозного вида | `KvXrCapabilities.Passthrough()` | отражением искала `OpenXRSettings.GetSettings()`/`ActiveFeatures` — **таких членов в OpenXR 1.15.1 нет**; плюс считала признаком passthrough включённую фичу CompositionLayers. Ответ всегда «неизвестно» |
| Фичи OpenXR для Android | `PassthroughFeature`, `PICOSpatialMesh`, `PICOSpatialAnchor` | `m_enabled: 0` — выключены все |
| Режим MR | `KvXrMrRoom.MrActive` | требовал тумблер `GetPassthrough()`, а `SetPassthrough` **не вызывался ниоткуда**, значение по умолчанию 0 → `MrActive` всегда false, вся ветка MR — мёртвая |
| Постановка робота | `KvXrMrRoom.PlaceRobot()` | ставила в `tableCenter = (0,0,0)` — **в место оператора** (робот «исчезал») |
| Реальная поверхность | — | `Physics.Raycast` не видит реальный стол: у него нет коллайдера |
| Якорение | — | не было |
| Масштаб 1:1 | — | робот метрический, но это нигде не проверялось числом |

## ИЗВЕСТНЫЕ ЛОВУШКИ (найдены в этой сессии)

| Ловушка | Как выглядит | Как лечить |
|---|---|---|
| «Ставлю робота» — а он внутри себя | позиция в (0,0,0) на высоте стола | ставить в точку реальной поверхности, извлекая робота из стенда |
| Фичи OpenXR выключены | проба «нет», хотя шлем умеет | включать инструментом, проверять перечитыванием ассета |
| `EnableVideoSeeThrough` «врёт» | свойство ставит флаг до проверки | проверять `isExtensionEnable` + `IsPassthroughSupported` |
| `IsPassthroughSupported()` падает в редакторе | `DllNotFoundException` | вызов только на Android |
| На реальном столе нет коллайдера | луч уходит в пустоту | меш комнаты → невидимые коллайдеры → луч по своему списку |
| Порядок `Start` не гарантирован | режим ещё не определён → MR не включается | `KvXrPlatformModeSelector.EnsureApplied()` |
| Править `XrMain.unity` нельзя | пин SHA256 в тесте | MR собирается в рантайме |
| Два агента в одном проекте | чужие правки/сборки | `Docs/КООРДИНАЦИЯ_АГЕНТОВ_MR_AR.md`, блокировка `.unity_lock`, коммит `[MR]` только своих файлов |

## ЧЕГО ЖДАТЬ НЕ СТОИТ

- **Кнопки «включить MR» не будет** — так требует ТЗ (S1.7). Режим определяется железом.
- **Визуальную проверку комнаты делает владелец в надетом шлеме.** Агент без шлема видит только
  журнал `adb`.
- **Quest 3 — вторым шагом**, отдельной сборкой: сначала PICO (основной шлем), чтобы при поломке
  было видно, что именно её сломало.
- **Масштаб 1:1 не переделывает виртуальные стенды 14,4 м.** В MR они скрываются: реальный стол —
  и есть стол. Масштаб 1:1 относится к роботу, и он проверяется замером.
