## 1. АРХИТЕКТУРА (решение и почему)

### 1.1 Одно приложение, два режима, один APK

```
BootAr.unity  (индекс 0, новая)
   │  ждёт инициализации XR, смотрит activeLoader
   ├── OpenXRLoader  → XrMain.unity   (VR/MR — прежний путь, не меняется)
   ├── ARCoreLoader  → ArMain.unity   (AR — новое)
   └── ни одного     → экран Ж1 «устройство не поддерживает AR», без падения
                        (+ кнопка «Продолжить в VR» — только как страховка для шлема)
```

Почему так: XR Management перебирает лоадеры и берёт **первый успешный**. OpenXR первым —
шлем получает OpenXR; на планшете OpenXR не поднимается и успешным становится ARCore.
Никакой настройки до запуска (требование S1.7).

### 1.2 Сцена AR — отдельная, копия XR-стека

`ArMain.unity` собирается инструментом `KvArSceneBuilder` **как копия `XrMain.unity`** и правится:

| Что | Действие в ArMain |
|---|---|
| `ARSession`, `XROrigin`, `ArCamera` (Camera+AudioListener+`ARCameraManager`+`ARCameraBackground`+`TrackedPoseDriver`) | добавлено |
| `ARPlaneManager` (horizontal, префаб плоскости), `ARAnchorManager`, `ARRaycastManager` | добавлено |
| `KvXrHeadTracking` (пишет позу каждый кадр) | **выключен** — камерой владеет AR Foundation |
| `KvXrLocomotion` (телепорт/повороты) | **выключен** — оператор стоит на своём полу |
| `KvXrMrRoom`, `KvXrHangarAnchor`, `KvXrSceneContent` (MR/ангар/стенды 14,4 м) | **выключены** |
| `XrHangar` | **погашен** — фон даёт камера |
| Логическая голова `XrCamera` | объект оставлен, **рендер выключен**, поза копируется мостом |
| Меню 110 команд, стартовое меню, окна, `KazistovVvUIManager`, `XrEventSystem` | **как есть** — это и есть «весь функционал» |

Почему база — XR-стек, а не ПК-сцена: в шлеме уже проверены меню 110 команд, метрические столы,
автостол по вылету, спавн роботов 12 моделей, выбор объекта; ПК-сцена — HDRP/мышь/1920×1080 и
для пальца не годится (разведка 02.11.2026).

### 1.3 Мост AR-камеры в XR-стек

`KvArRigBridge` каждый `LateUpdate` копирует **мировую позу AR-камеры** в логическую `XrCamera`
(её рендер выключен). Все прежние компоненты интерфейса продолжают работать без правок.
Мир при этом привязан к якорю, а не к камере (запрет S3.1).

### 1.4 Постановка на реальную плоскость

`KvArPlacement`: ожидание плоскостей (A2) → маркер под центром экрана (`ARRaycastManager`,
`TrackableType.Planes`) → тап → `ARAnchorManager.AttachAnchor(ARPlane, Pose)` (запасной путь —
`TryAddAnchorAsync`) → `ArLabRoot` ребёнком якоря → робот основанием ровно в точку стола.
Если тап по столу, а мир уже поставлен — работает выбор объекта/подтверждение точки.

### 1.5 Касания (`KvArTouchInput`)

| Жест | Действие | Через что |
|---|---|---|
| тап по иконке меню | команда | луч из точки касания → `KvXrGroupPanel.TryAim`/`PressIndex` |
| тап по роботу/столу | выбор (кольцо + строка статуса) | `RegisteredObject` + `RobotController` |
| тап по столу (до постановки) | поставить якорь и робота | `KvArPlacement.TryPlaceAt` |
| тап по пустому месту | подтверждение точки | `TrajectoryFlowController.UpdateAim(...)` |
| перетаскивание | поворот вида вокруг сцены | поворот `ArLabRoot` вокруг якоря |
| щипок | масштаб ВИДА (угол обзора), не робота | `KvArRigBridge.ZoomView` |
| поворот двумя пальцами | поворот вида | `ArLabRoot` |
| тап двумя пальцами | отмена (Esc) | `cancel=true` в поток |
| кнопка «Двигать точку» | перетаскивание двигает точку | `UpdateAim(moveToggle/moveAxis)` |

### 1.6 Отказы (Блок Ж)

`KvArSessionController`: `Unsupported` → сообщение Ж1; `NeedsInstall` → кнопка «Установить ARCore»
(`ARSession.Install()`, исключения ловятся); нет разрешения камеры / `CameraUnavailable` → Ж2;
`notTrackingReason` (свет/мало признаков/быстрое движение) → подсказка в журнал. Приложение не падает.

### 1.7 Меню и команды в AR

`KvXrObjectFactory` получил три **необязательных** хука (`SpotOverride`, `TableFloorFixup`,
`RobotPositionFixup`; по умолчанию `null` → VR/ПК не меняются). AR-сцена включает их: «точка перед
оператором» становится точкой на найденной плоскости, высота стола/робота отсчитывается от якоря.
Объекты, созданные командами меню, `KvArWorld.AdoptLooseObjects` переносит под якорь.
