# ДЕРЕВЬЯ КОМАНД ПО ГРУППАМ — ГЛУБОКИЙ РАЗБОР ПОВЕДЕНИЯ (реестр `KvCommands`)

Дата: 13.11.2026 · Версия: v1 · Зона: **реестр команд `KvCommands`** — то, что реально происходит
при вызове `KvCommands.Invoke(id)`. Дополняет, а не дублирует `ДЕРЕВЬЯ_КНОПОК_ПК.md` (там —
деревья кнопок/меню и §1.7 с обработчиками file:строка), `ДЕРЕВЬЯ_КНОПОК_ШЛЕМ.md` и
`ДЕРЕВЬЯ_КНОПОК_AR.md`: здесь каждая команда разобрана **по телу обработчика** — какие системы
трогает, какие состояния меняет, где проверки и тихие отказы, какая зависимость от железа, какой
дефект/заглушка и какой потенциал.

## Как читать

* **Пути** даны от `Assets/_Project/`; `01_Scripts/Features/FeatureHub.cs:642` — файл и строка
  **метода-обработчика**; номер в скобках «делегат `…:1244`» — строка регистрации команды
  (именно её читает статический анализ тестов).
* **Обработчик** — это не всегда «метод с именем команды»: у большинства команд `Execute` —
  анонимный `delegate` в блоке регистрации, который зовёт метод сервиса. Указан и метод, и
  регистрация.
* **Глубина**: подтверждено чтением кода. Всё, что помечено «по замеру/по документам», — из
  `КОНСПЕКТ_КНОПОК_таблица.md` и отчётов самопрогона.

## Общие механизмы реестра (один раз на все 161 команду)

1. **Единая точка входа** `KvCommands.Invoke(id)` — `06_KazistovVv_UI/03_Scripts/Core/KvCommands.cs:131`.
   Порядок: нет id → `false`; `!Enabled` → отказ с строкой в `KvUiJournal` («недоступна: сейчас
   нельзя» / «недоступна: в разработке») и `false`; `Execute != null` → вызов, **затем**
   `ExecutedCount++` и строка журнала «выполнена»; `Execute == null` → строка «без обработчика»,
   счётчик НЕ растёт. Отказ — тоже событие журнала.
2. **`Enabled = !Stub && (IsEnabled == null || IsEnabled())`** (`KvCommands.cs:41`). `Stub=true`
   в рантайме сейчас **нигде не регистрируется** (проверено поиском: остались только тестовые
   упоминания) — заглушки `edit.undo/redo`, `file.export`, `tool.measure`, `tool.grid`,
   `file.import` перерегистрированы настоящими обработчиками (комментарий
   `KazistovVvUIManager.cs:1566`).
3. **Исключения обработчика НЕ перехватываются** (`KvCommands.cs:148` — прямой вызов) — известная
   открытая задача: упавший обработчик роняет нажатие и не даёт строку «выполнена». Поэтому
   «дефект: возможен выброс» ниже упоминается только там, где исключение реально вероятно.
4. **`Hotkey` — только подпись** в подсказке/меню; реальные бинды лежат в `KvBindings.cs`.
   Конфликт F12 (`health.toggle` = F12 в `KvStageHub.cs:754` и `help.hotkeys` = F12 в
   `KazistovVvUIManager.cs:1494`) — обе команды заявлены на одну клавишу, в окне биндов
   конфликт не виден, потому что F12 мониторинга в `KvBindings` не зарегистрирован.
5. **Порядок регистрации и перекрытие**: `KazistovVvUIManager.RegisterCommands`
   (`KazistovVvUIManager.cs:1171`) вызывает `KvCommands.Clear()`, затем свои команды,
   `KvRobotCommands.RegisterModels` (`:1304`), `FeatureHub` (`:1590`), `KvStageHub` (`:1593`),
   `KvStageHub2` (`:1596`), `KvStageHub3` (`:1599`), `KvStageHub4` (`:1604`). Повторный id
   **заменяет** команду целиком (`KvCommands.Register`, `KvCommands.cs:91`).
6. **Группы** — данные `KvToolbarGroups.Build` (`06_KazistovVv_UI/03_Scripts/Zones/KvToolbarGroups.cs:70`):
   8 групп, 122 id. Тулбар рисуется **только** из `group.Commands`
   (`KazistovVvUIManager.cs:1156`), поэтому **39 зарегистрированных команд не имеют кнопки в
   тулбаре** — они доступны из строки меню (`MenuPath`) и палитры (`ui.palette`). Все 161
   зарегистрированы, мёртвых id в группах нет (сверено программно).
7. **Журнал действий**: `KvUiJournal.Command` (`KvCommands.cs:246`) пишет в `KvActionLog`
   (файл `Logs/actions_*.log`) с защитой от исключения. Служебные сообщения сервисов
   (`Message`-события) попадают в тот же журнал через `OnServiceMessage` всех четырёх хабов
   (`KvStageHub.cs:146`, `KvStageHub2.cs:139`, `KvStageHub3.cs:119`, `KvStageHub4.cs:258`).
   **А `KazistovVvUIManager.Log()` (`:664`) пишет только в консоль Unity** и только при
   `logUiEvents` — на шлеме/планшете такой причины не видно. Это главный класс дефектов ниже.

## 1. ГРУППА «РОБОТ» (21 команда)

### `robot.switch`
* **Обработчик:** `KazistovVvUIManager.SwitchRobot` — `06_KazistovVv_UI/03_Scripts/Core/KazistovVvUIManager.cs:2986` (делегат `:1291`).
* **Поведение:** собирает **все** `RobotController` (`FindObjectsInactive.Include`), отбрасывая
  скрытые (`RuntimeRegistry.IsHidden`); при `robots.Count < 2` — **молча выходит**. Находит
  индекс активного (`rc.isActive`), берёт следующий по кругу, `ActivateRobotOnly`
  (`:3023`) выключает все остальные, тулбару передаёт тип верстака (SCARA → сегмент 1),
  пишет `Log("Активный робот: …")` — **в консоль Unity, не в журнал действий**.
* **Доступность/исключения:** `IsEnabled = CountRobots() > 1` (`:1292`, функция `:1607` — та же
  фильтрация скрытых). При одном роботе кнопка серая, `Invoke` откажет и запишет в журнал
  «недоступна: сейчас нельзя» — **честный отказ, подтверждён кодом**.
* **Дефект:** причина переключения («робот один») на экране не проговаривается отдельно — её
  даёт только строка отказа в журнале; имя нового активного робота уходит в консоль, а не в
  `KvActionLog` (разбор записи на шлеме не покажет, кто стал активным).
* **Потенциал:** список роботов с превью и явной отметкой активного; индикация в статус-баре.

### `robot.playpause`
* **Обработчик:** делегат `KazistovVvUIManager.cs:1223` → `TrajectoryFlowController.Motion.SetPaused(!Paused)`; реализация `MotionExecutor.SetPaused` — `01_Scripts/Trajectory/MotionExecutor.cs:68`.
* **Поведение:** читает `f.Motion.Paused` и переключает; `SetPaused` без executor — молча ничего
  не делает. `Paused` (`MotionExecutor.cs:65`) — это пауза **исполнителя**, State Machine
  (`FlowState`) не затрагивается, траектория не сбрасывается; `IsRunning`
  (`:62`) = `executor != null && executor.IsRunning`.
* **Доступность/исключения:** `IsEnabled = Flow != null && Motion != null && Motion.IsRunning`
  (`:1236`) — **кнопка доступна ТОЛЬКО пока робот едет**. `IsChecked = Motion.Paused`
  (`:1231`), `IconChecked = "play"`. Если движения нет — команда недоступна, `Invoke` откажет
  со строкой в журнале.
* **Дефект:** из `IsEnabled` следует, что «нужен выбранный робот» — **неверно**: нужен **идущий
  поток движения**. В AR по замеру 11.11 кнопка была `interactable=false` именно поэтому, а не
  из-за выбора робота (`КОНСПЕКТ…` §4 утверждает обратное — см. §11).
* **Потенциал:** состояние ▶/⏸ на кнопке уже есть (`IconChecked`) — показывать подсказку
  «нажмите после запуска», чтобы серая кнопка не читалась как поломка.

### `robot.stop`
* **Обработчик:** делегат `KazistovVvUIManager.cs:1251` → `Motion.Stop()` → `MotionExecutor.Stop`
  — `01_Scripts/Trajectory/MotionExecutor.cs:171` (`executor?.Stop(SafetyReason.OperatorStop)`).
* **Поведение:** штатный стоп оператора: `SafetyReason.OperatorStop`, дальше SafetyGate решает,
  что делать с потоком. Ничего не сбрасывает (в отличие от `estop`).
* **Доступность/исключения:** та же `IsEnabled = Motion.IsRunning` (`:1258`) — без идущего
  движения кнопка серая и `Invoke` откажет.
* **Дефект:** `Motion.Stop()` без executor — тихий `?.`; в `Execute` ещё и ранний выход при
  `f == null || f.Motion == null` (`:1254`) — но до него `IsEnabled` не даёт дойти.
* **Потенциал:** состояние стопа на кнопке (цвет/индикатор), блокировка с подсказкой причины.

### `estop`
* **Обработчик:** `FeatureHub.EmergencyStop` — `01_Scripts/Features/FeatureHub.cs:642` (делегат `:1244`).
* **Поведение:** один `try/catch` на всё: `Motion.Stop()` → `Executor.Stop(OperatorStop)` →
  `flow.EndExternalMotion()` → `Recording.StopAll("аварийная остановка")` →
  `PickAndPlace.Cancel(...)` → `Scenarios.Stop(...)` → `flow.ResetFlow("АВАРИЙНАЯ ОСТАНОВКА")`.
  После блока (даже если исключение было поймано): `Audio.PlayAtRobot(EmergencyStop)`,
  `Haptics.OnEmergencyStop()`, строка в `KvActionLog`, красный `SetPlanStatus`, пересборка
  дерева. Исключение гасится `Debug.LogWarning("[Estop] …")` — **единственная команда,
  защищённая от падения**.
* **Доступность/исключения:** без `flow` (нет `TrajectoryFlowController`) — **молча выходит**
  (`:645`), ни строки, ни звука.
* **Дефект:** тихий выход при отсутствии потока (на десктопе без сцены нажатие «не работает»
  без объяснения); звук/вибро — от `KvSpatialAudio`/`KvHaptics`, при отсутствии датчиков
  вибрации остаётся только звук.
* **Потенциал:** состояние «авария» на кнопке (цвет/звук/вибро в шлеме) и журнал аварии с
  таймкодом — сейчас авария нигде не «залипает».

* **Потенциал:** вернуть меша 10 моделей (главный долг каталога); до этого — честная карточка

## 2. ГРУППА «ТОЧКА И ТРАЕКТОРИЯ» (13 команд)

### `point.select`
* **Обработчик:** делегат `KazistovVvUIManager.cs:1184` → `FreeFlyCameraController.leftHandEnabled = !…` (`CameraRig`).

### `path.select`
* **Обработчик:** делегат `KazistovVvUIManager.cs:1203` → `FreeFlyCameraController.rightHandEnabled = !…`.

* **Дефект:** `valid.run` **не имеет `IsEnabled`** — кнопка активна в любом состоянии потока,
  отказ приходит текстом, но не сопровождается состоянием кнопки; вкладка — тихий отказ.
* **Потенциал:** блокировка «ПУСК» до готовности проверки + причина в подсказке.

### `logtools.tab` / `logtools.export`
* **Обработчик:** `OpenTab("logtools")` (`:939`) / `ExportLogView` → `LogTools.ExportVisible()` (`:582`, делегат `:941`).
* **Поведение:** фильтр/поиск/цвета журнала; выгрузка **только видимых** записей в файл.
* **Доступность/исключения:** `Instance == null` → молча выходит (вкладка).
* **Дефект:** тихий отказ вкладки; путь выгрузки — только в сообщении сервиса (журнал).
* **Потенциал:** выгрузка с фильтром по времени/типу из статус-бара.

### `graphics.tab` / `graphics.detect` / `graphics.benchmark` / `graphics.metrics` / `graphics.reset`
* **Обработчик:** `KvStageHub4.OpenGraphicsTab` (`:991`, делегат `:951`) → `KazistovVvUIManager.ShowSettings(KvSettingsView.GraphicsTabIndex)`; `graphics.Redetect(true)` (`:956`), `StartBenchmark(5f)` (`:961`), `KvGraphicsUi.ToggleMetrics()` (`:966`, `IsChecked = KvGraphicsUi.MetricsVisible`), `ResetToAuto()` (`:972`).
* **Поведение:** раздел «Графика» панели настроек; повторное автоопределение GPU/памяти/ЦП и
  пересчёт пресета; бенчмарк 5 с (средний/минимальный FPS, просадки); оверлей метрик
  (FPS, время кадра, вызовы, треугольники, видеопамять); возврат в режим «Авто».
* **Доступность/исключения:** сервис `KvGraphicsService` запускается в `Awake` хаба
  (`EnsureStarted`, `:129`); в пакетном режиме `Available == false` — команды `detect/benchmark/reset`
  при `graphics == null` молча выходят (проверка `if (graphics != null)` прямо в делегате);
  `graphics.tab` — `ui == null` → молча выходит.
* **Дефект:** три из пяти (`detect`, `benchmark`, `reset`) — **тихие отказы** при недоступной
  службе; результат бенчмарка/детекта виден только в сообщении сервиса, не в статусе.
* **Потенциал:** показывать «пресет: X → эффективный Y» на кнопке, авто-пресет по FPS.

### `scara.recalibrate`
* **Обработчик:** делегат `KvStageHub4.cs:981` → `if (hub.flow != null) hub.flow.RebindKinematics("команда оператора")`.
* **Поведение:** пересчёт пределов хода призмы и зановая привязка потока — **тяжёлая операция,
  только по явному запросу** (автоматически не выполняется).
* **Доступность/исключения:** `flow == null` → молча выходит; выполняется синхронно (стоп-кадр).
* **Дефект:** тихий отказ без потока; нет предупреждения «операция тяжёлая, кадр встанет»;
  для роботов без SCARA команда бесполезна, но активна всегда.
* **Потенциал:** `IsEnabled` по типу активного робота (SCARA) + индикатор выполнения.

* `waypoint.earlier`, `waypoint.later`, `waypoint.delete` — нет выбранной точки или граница
  списка → `false` без единой строки.

* `scenarios.run` — сценариев нет → молчаливый выход (`KvFeatureWindow.cs:1191`).
* Все `*.tab` (`constr/wp/calib/payload/export/import/collision/lab/cameras/forces/heat/report/
  net/script/bt/mat/titles/vo/fail/valid/logtools/graphics` — 22 команды) —

  открывается на текущей вкладке без объяснения.
* `post.auto`, `post.auto.selected`, `post.smooth/timeoptimal/energy`, `workbench.toggle` —
  сервис `null` → молчаливый выход.
* `startmenu.show`, `demo.quick`, `tut.toggle`, `tut.restart`, `ui.palette`, `help.hotkeys` —
  соответствующий объект `null` → молчаливый выход.

  при недоступном железе → молчаливый выход или работа «вхолостую» (флаг включается, данных нет).

того, как выяснится, что обработчик молча вышел, — самопрогон UI может «зазеленить» такую
кнопку. Это структурный дефект, а не единичный.

### 11.2 Опровержено / исправлено (5 пунктов — **явный список расхождений**)

1. **`robot.playpause` / `robot.stop`: «нужен выбранный робот» — неверно.** Реальная
   причина серой кнопки (`interactable=false` в AR) — `IsEnabled = Motion.IsRunning`:
   команда доступна **только пока робот движется**. Выбранный робот ни при чём; без
   запущенной траектории кнопки серые **по замыслу**.
2. **`pose.goto` — «есть» (переезд в позу) — не соответствует коду.** Обработчик
   `hub.Window.Show(1)` только открывает вкладку «Позы»; никакого движения робот не выполняет.
   Обещание в `Description` («Плавный переезд робота в выбранную позу») не выполняется.
3. **«Часть „без эффекта“ без причины (screenshot/video/import/session)» — причины В КОДЕ ЕСТЬ.**
   `record.toggle` → «робот потока не готов»; `record.play` → 4 проверки (нет записей / робот
   едет / другой DOF / другой робот); `session.load` → «сессий нет»; `export.robot` → «Нет
   траектории: выберите точку (Z + ЛКМ)…». Расхождение не в отсутствии причины, а в том, что
   **причина уходит в `KvActionLog`/консоль и не показывается оператору на экране**.
4. **`video.toggle`: описание «MP4 через Unity Recorder» на устройстве неверно** — в APK
   Unity Recorder нет, команда пишет последовательность PNG-кадров + манифест
   (`KvCaptures.cs:333-347`). В §4 это не отмечено.
5. **`file.export` в §4 назван командой экспорта («Экспорт/Запись») — по коду это „показать
   папку данных“:** команда печатает пути каталогов в консоль/журнал, файл не создаётся.
   Пункт меню при этом подписан «Файл/Папка данных» — совпадает с кодом, но строка §4
   («Экспорт…») вводит в заблуждение.

### 11.3 Утверждения §4, которые код НЕ подтверждает и НЕ опровергает (нет данных)

### 11.4 Находки, которых в §4 нет вообще

1. **39 команд не имеют кнопки в тулбаре** (все `KvStageHub4` + часть «Прочего»): доступны
   только из строки меню и из палитры. §4 раскладывает команды по 8 группам так, будто все
   группы полные.
2. **`voice.toggle` включает микрофон, но распознавания речи нет** — ни один класс не
