**Честная оговорка про «зелёный» отчёт гейта.** Гейт вернул код 1 и записал `ok: false`
с `timeout: true`: **процесс Unity в этом окружении не завершается сам** — редактор печатает
`Shut down.`, но остаётся в памяти, и скрипт снимает его по таймауту. К содержанию проверки
это не относится: все числа (0 ошибок, 0 предупреждений, 0 потерянных скриптов, настройки без
изменений) получены из лога и напечатаны. **Признак «работа сделана», а не «процесс вышел» —
это `Shut down.` в логе плюс отсутствие `error CS`.** В проект стоит дописать это в
`Docs/DEVELOPER_README.md` (сделано) и в скрипты проверки.

### Найденное ограничение инструмента проверки (важно для будущих сессий)

`Assembly-CSharp*.csproj` — **генерируемые файлы с ЯВНЫМ списком** `<Compile Include=…>`, поэтому
**новый `.cs` не попадает в `dotnet build`, пока Unity не откроет проект** (или пока файл не добавят
в список вручную). Из-за этого первая проверка «0 ошибок» не покрывала новые файлы. В этой сессии
пять новых файлов добавлены в списки вручную (`KvXrQuickPanelLayout.cs`, `KvXrWindowState.cs`,
`KvLocExtra5.cs`, `KvXrInputTests.cs`, `KvXrOverlayTests.cs`); Unity перегенерирует `.csproj` при
следующем открытии — правка временная. **В `Docs/DEVELOPER_README.md` это стоит дописать.**

* при «холодном» IL-коде Unity тратит на сборку **8–17 минут** (`Tundra build success (622 s)`,
