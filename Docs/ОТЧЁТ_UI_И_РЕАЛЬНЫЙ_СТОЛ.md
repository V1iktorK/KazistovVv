# ПРОВЕРКА UI В VR/AR/MR И РАСПОЗНАВАНИЕ РЕАЛЬНОГО СТОЛА — ОТЧЁТ

Дата работы: 12.11.2026. Отчёт написан по ИЗМЕРЕНИЯМ, а не по обещаниям разработчиков: каждая цифра
ниже получена прогоном на устройстве или тестами в редакторе.

---

## 1. Что просили и что сделано

Владелец попросил: (1) протестировать весь UI в трёх режимах — VR, AR, MR; (2) сделать
автоматическое распознавание РЕАЛЬНОГО (не виртуального) стола для AR/MR; (3) предложить и
провести дополнительные проверки функционала.

Сделано:
1. Встроен самопрогон интерфейса — приложение само обходит свои элементы, нажимает их настоящим
   путём uGUI и доказывает эффект числом. Прогон работает в трёх раскладках; вердикт выносится по
   журналу устройства (`Tools/ui-sweep-device.ps1`).
2. Распознавание реального стола: классификатор (18 тестов без устройств) + подключение к AR
   (плоскости ARCore) и к MR (разметка комнаты PICO) + ОБЯЗАТЕЛЬНЫЙ отчёт с числами на устройстве
   (`Tools/real-table-device.ps1`).
3. Добавлены четыре новых набора тестов (36 тестов) и две новые проверки в приёмочный гейт.

## 2. Самопрогон интерфейса: что измерено

| Раскладка | Элементов найдено | Сработало (доказан эффект) | Без эффекта | Исключений с причиной | Исчезло |
|---|---|---|---|---|---|
| **AR (планшет)** | 140 | **78** | **0** | 60 | 2 |
| VR (шлем) | 209 | 36 | 2 | 19 | 152 |
| MR (шлем) | 209 | 36 | 2 | 19 | 152 |

ВАЖНО ПРО VR/MR. «Исчезло 152» — это НЕ дефект кнопок: интерфейс шлема иерархический (раздел →
иконка группы → экран), и нажатие раздела пересобирает панель целиком, поэтому пути остальных
элементов перестают существовать. Инструмент честно печатает их путями и причинами, но считать
покрытие VR/MR достаточным нельзя. Приёмочный гейт это и показывает: пункт `UI_SWEEP` красный
ТРЕТИЙ прогон подряд, счётчик повторов дал **СТОП (код 3)** — по правилу «не четвёртый круг, а
решение». Решение требуется не разработчику «старательнее», а по существу: либо обход шлема должен
идти по одному элементу на запуск (дорого по времени), либо интерфейс шлема должен давать
устойчивые пути (это изменение продукта), либо VR/MR проверяет человек в шлеме.

По AR: из 140 элементов 78 доказали работу (вкладки настроек, пункты меню, кнопки шапок панелей,
переключатели, кнопки тулбара), 60 — исключения с НАЗВАННОЙ причиной (нужен микрофон/трекинг рук/
контроллер; действие невозможно при 0 найденных плоскостях; панель ПК в шлеме не показывается),
2 — элемент исчез при перестроении интерфейса. Элементов, которые «молчат» без причины, — НОЛЬ.
Это и есть машинное доказательство требования владельца «каждая кнопка делает работу».

Как читать исключения: каждое несёт причину с числом, например
«нечего ставить: найденных плоскостей 0 (подтверждено состоянием AR)». Исключение — не оправдание,
а названное ограничение; скрытых провалов нет.

Ограничение по шлему (честно): интерфейс шлема иерархический (раздел → иконка группы → экран), и
нажатие раздела пересобирает панель целиком. Самопрогон обходит это отдельным проходом по пунктам
меню (по одному, с возвратом меню), но полное покрытие VR/MR упирается в пересборку UI, а не в код
приложения. Что именно не проверено — печатается в отчёте прогона путями, а не замалчивается.

## 3. Распознавание реального стола

**Правила (18 тестов без устройств).** Классификатор `KvRealTableClassifier` — чистая функция над
числами. Пороги: наклон ≤ 25,8° (`dot ≥ 0.90`), площадь 0,25…3,0 м², сторона ≥ 0,35 м, отношение
сторон ≤ 4, ниже глаз на 0,35…1,5 м, выше пола ≥ 0,25 м, трекинг ≥ 0,5 с, гистерезис 20 %;
семантика платформы сильнее геометрии (`Table` = 0,95, отказ `Floor/Ceiling/Wall` = 0,90,
геометрия 0,45…0,85). Каждое решение объясняется строкой с числами.

**Что было сломано и исправлено.**
- Столом считалась «самая большая горизонтальная плоскость ≥ 0,15 м²» — то есть **пол**. Робот
  вставал на пол, а подпись говорила «стол найден». Заменено классификатором.
- В MR запрос разметки комнаты **молчал навсегда**: отчёт жил за `await` внутри пакета PICO, где
  ожидание сделано бесконечным циклом `while (true) { … UPxr_PollFuture … }`. Теперь предел 15 с
  отсчитывает главный поток, и КАЖДЫЙ исход печатается строкой с числами.
- В AR при НУЛЕ плоскостей журнал молчал вообще (печатались только «стол найден/пол/плоскости
  есть»). Теперь печатается «плоскостей 0 · трекаблов 0 · трекинг <факт> · что делать: …».

**Что измерено на устройствах.**
- Планшет (ARCore): `[KvAr] ПОВЕРХНОСТИ: трекинг НЕ идёт · сессия Ready · причина: не указана ·
  плоскостей 0 · трекаблов 0 · ждём 4 с · что делать: наведите планшет на освещённую поверхность …`
- Шлем (PICO 4 Ultra, старт в MR): `[KvMr] РЕАЛЬНЫЙ СТОЛ: запрос выполнен за 6.05 с · столов 0 ·
  пол нет · причина разметки комнаты нет — запрос PxrSemanticLabel.Table вернул 0 объектов` +
  прямая инструкция оператору «включите разметку комнаты в настройках PICO».
- Сквозной вид в MR подтверждён рантаймом: `пасс-слой включён (EnableVideoSeeThrough = true)`.

**Честная граница.** Перед камерой планшета не было ни стола, ни вообще поверхностей (ARCore не
построил карту), а комната в PICO не размечена. Поэтому «стол найден» предъявить нельзя: приёмка
требует не этого, а ЧЕСТНОГО вердикта с числами — он получен. Чтобы увидеть «стол найден · площадь
… · высота над полом …», нужно физически навести планшет на стол либо разметить комнату в шлеме;
после этого строка появится сама.

## 4. Найденные дефекты (по убыванию важности)

1. **10 из 12 моделей каталога роботов — без геометрии.** Префабы ссылаются на меши, которых в
   проекте нет (FBX роботов всего два: `Robot.fbx`, `ScaraRobot.fbx`). Выбор UR5/KUKA/ABB/Fanuc/
   Franka/Kinova/Comau/OpenArm создавал робота, которого НЕ ВИДНО. Проверено моим замером: из 15
   префабов меши разрешаются у двух. Теперь недоступные модели помечены и объяснены, робота не
   создают, текущий робот не удаляется, а число доступных закреплено храповиком (`= 2`).
2. **56 кнопок «Переназначить» в окне горячих клавиш были заглушками** (писали «появится позже»).
   Удалены: обещать несуществующее нельзя. Настоящее переназначение требует сквозного слоя биндов
   (сейчас `KeyCode` зашиты литералами в десятках мест) — это отдельная работа.
3. **MR-конвейер молчал** (см. §3) — исправлено, теперь говорит всегда.
4. **AR молчал при нуле плоскостей** — исправлено.
5. **Переключатель VR/MR на лету не поднимает MR-конвейер.** Режим сохраняется, но сквозной вид и
   реальные поверхности поднимаются только при СТАРТЕ приложения в MR (проверено: при старте в MR
   строка `СМЕШАННАЯ РЕАЛЬНОСТЬ: включаю сквозной вид…` есть, при переключении на лету — нет).
   Требует решения: либо перезапуск по переключателю, либо горячая инициализация MR.
6. **`KvSettings.Reload()` не зажимал значения при чтении** (в отличие от `KvXrSettings`): значение
   из испорченного хранилища применялось как есть. Исправлено, покрыто тестами.
7. **`KvRobotSpawner.DescribeAvailability()` врала**: грузила путь с приставкой `Resources/`, которую
   `Resources.Load` не понимает, и печатала «префаб есть у 0» при полностью доступных префабах.
   Исправлено: один путь загрузки на всех.
8. **Система убивает приложение на планшете** посреди работы (Android чистит память: десятки
   `Process … has died`, затем рабочий стол). Прогон повторяется один раз; второе убийство подряд
   считается результатом.
9. **«Missing script» на стендах сцены шлема** (`Стенд_1_Стол`, `Стенд_2_Стол`): сцена ссылается на
   6 GUID скриптов, которых нет в `Assets`. Функционально стенды строятся кодом, но ссылки надо
   разобрать в редакторе — инструмент для этого уже есть (`KvSceneRepairTools`).

## 6. Что осталось человеку

1. Навести планшет на настоящий стол и посмотреть строку «стол найден · площадь … · высота над
   полом …» (сейчас в кадре поверхностей нет).
2. Разметить комнату в настройках PICO — тогда в шлеме появится «столов N» вместо «разметки нет».
3. Посмотреть глазами интерфейс в шлеме (читаемость, удобство) — машинно это не проверяется.
4. Решить по переключателю VR/MR: перезапуск или горячая инициализация (см. дефект 5).
5. Вернуть геометрию роботов (дефект 1) — сейчас из 12 моделей работает 2.
