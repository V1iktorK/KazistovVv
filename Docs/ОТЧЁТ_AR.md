### 2.4. ДЕФЕКТ, НАЙДЕННЫЙ ПЕРВОЙ СБОРКОЙ (исправлен)

**Симптом:** первая сборка APK (03.11.2026, 08:03–08:14) в журнале написала:
```
[KvXr] Лоадеры XR пересобраны на активный OpenXR: Standalone: лоадеров 1 · Android: лоадеров 1.
       Mock HMD/Simulation/ARCore отключены…
```
**Причина:** сборщик `KvXrTools.BuildAndroidApk()` вызывает `KvXrTools.ConfigureXrLoaders()`,
а тот исторически оставлял в списке Android РОВНО ОДИН лоадер — OpenXR (приложение было только
для шлема). При одном APK на два устройства это гарантированный отказ AR: на планшете OpenXR
не поднимается, а ARCore выключен сборщиком — ошибки сборки при этом НЕТ, APK собирается нормально.

**ВТОРОЙ ДЕФЕКТ ТОГО ЖЕ МЕСТА (найден 08:40):** `BuildAndroidApk` собирал APK с жёстким списком
сцен `new[] { XrScenePath }` — в APK попадала только VR-сцена, а `BootAr` (выбор режима) и
`ArMain` (AR) не попадали вовсе. Ошибок сборки нет: APK собирается, просто урезан.
**Исправление:** `EnabledBuildScenes()` берёт включённые сцены из Build Settings в их порядке
(`BootAr → XrMain → ArMain`); ПК-сцена `MainScene` (HDRP/мышь) в APK исключена намеренно —
на устройстве она не исполняется и тянет компоненты конвейера, которого на Android нет.

**Исправление:** `ConfigureXrLoaders` теперь для Android ставит ДВА лоадера в порядке
`OpenXR → ARCore` (Standalone по-прежнему OpenXR), `VerifyOpenXrActive` проверяет порядок,
добавлен тест-сторож `ApkBuilder_KeepsArCoreLoaderForAndroid`. Это ровно случай «правка
в неисполняемой ветке» из прошлых сессий, только зеркальный: сборка исполняла ветку,
которая молча ломала новый режим.

## 6. КАК ПРОВЕРИТЬ НА ПЛАНШЕТЕ (инструкция владельцу)

1. **ARCore на устройстве.** Play Маркет → «Google Play Services for AR»:
   - устанавливается/обновляется → устройство подходит;
   - «несовместимо с устройством» → ARCore не поддерживается, AR не запустится (это ограничение
     устройства, а не приложения; приложение покажет понятное сообщение и не упадёт).
2. **Установка APK.** `adb install -r Builds\KazistovVv.apk` (или открыть файл на планшете и
   разрешить установку из неизвестного источника). Старый APK удалять не обязательно:
   подпись та же (`com.KazistovVv.app`).
3. **Запуск.** Приложение само определяет режим: на планшете с ARCore загрузится AR-сцена,
   в журнале (logcat) будет строка `[KvAr] РЕЖИМ: ДОПОЛНЕННАЯ РЕАЛЬНОСТЬ` и
   `[KvXr] РЕЖИМ: ДОПОЛНЕННАЯ РЕАЛЬНОСТЬ`.
4. **Камера.** Разрешение на камеру ARCore запросит сам (кнопка «Установить ARCore» появляется
   только если не установлены «Google Play Services for AR»).
5. **Постановка робота.** Водите камерой по столу 2–3 секунды → появится маркер на столе →
   коснитесь стола (или кнопки «Поставить») → робот встанет основанием на столешницу.
6. **Управление.** Тап по иконке меню — команда; тап по роботу — выбор (жёлтое кольцо);
   перетаскивание — поворот вида; щипок — масштаб вида (робот остаётся 1:1);
   «Переставить» — выбрать новое место; «Двигать точку» — режим перемещения точки.
7. **Меню.** Кнопка «Меню» открывает стартовое меню шлема; в нём столы, роботы, 12 моделей,
   двурукий. Дальше меню левой руки листается страницами — все 110 команд доступны.
8. **Что прислать для приёмки.** Скриншот/видео экрана + `adb logcat` (строки `[KvAr]`), если
   что-то не так: по строке `[KvAr] СОСТОЯНИЕ:` видно сессию, плоскости, якорь и кадры.

**На шлем PICO/Quest** ставится ТОТ ЖЕ APK: `BootAr` по активному OpenXR грузит прежнюю
`XrMain` — VR/MR не меняются (проверяется AR-агентом по `adb logcat`; визуально — владельцем).
