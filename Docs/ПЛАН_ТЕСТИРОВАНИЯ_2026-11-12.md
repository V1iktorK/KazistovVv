# ПЛАН ТЕСТИРОВАНИЯ — KazistovVv (Unity 6000.5.6f1)

Дата: 12.11.2026. Автор: инженер-тестировщик (MiMo). Документ живой: после каждой итерации
прогона раздел «Журнал итераций» дополняется измеренными числами, а не пересказами.

---

## 1. Объект и цель тестирования

**Объект.** Unity-тренажёр промышленных роботов KazistovVv: десктоп HDRP + шлем PICO 4 Ultra
(VR/MR, Vulkan) + планшет Redmi (AR, GLES3). Два робота (6-осевой, SCARA), UI в стиле FreeCAD,
каталог из 12 моделей роботов (2 с геометрией — храповик закрепляет).

**Цель.** Машинное доказательство требований владельца (дословно):
1. «главное — чтобы все кнопочки были заполнены функционалом» — каждая кнопка ДЕЛАЕТ работу;
2. автоматическое распознавание РЕАЛЬНОГО стола в AR и MR — вердикт с числами, никогда молча;
3. робот не появляется до закрытия меню, место выбирается правым (зелёным) лучом и фиксируется
   клавишей B;
4. левый луч красный (точка), правый зелёный (траектория), оба упираются в реальные и
   виртуальные поверхности по ОДНОМУ правилу;
5. логи: без спама (повторы 30 с), поза ≤10 Гц, ротация, UTF-8.

**Принцип приёмки.** Словам «я исправил» не верить. Вердикт выносит только прогон:
`pwsh -File Tools\acceptance-gate.ps1` → `exit 0`. Правки делает субагент-разработчик, приёмку
фиксирует тестировщик собственным прогоном.

## 2. Стратегия: 6 уровней

### Уровень 0 — статические сторожи (секунды, без Unity)
| Проверка | Что доказывает | Инструмент |
|---|---|---|
| 8 сторожей репозитория | структура, чистота дерева, целостность правил | `Tools/repo-guards.ps1` |
| SECRET | пароля подписи нет ни в tracked, ни в новых файлах | проверка SECRET гейта |
| P4_3_RATCHET | число тестов, читающих исходники, НЕ растёт (порог 56 файлов) | проверка P4_3_RATCHET |
| UI_STUBS | в реестре команд нет кнопок-заглушек (учитывая перерегистрации) | проверка UI_STUBS |
| BOM кириллических .ps1 | скрипты с кириллицей имеют UTF-8 BOM | шаг 2 ci-local |

### Уровень 1 — EditMode-тесты (ядро, без сцен)
- Набор: `Assets/_Project/08_Tests/Editor` (~129 файлов, ≥1264 тестов — порог гейта; фактическое
  число — в журнале итераций).
- Покрывают: траектории/IK/безопасность, настройки и клампы, локализацию, каталог роботов
  (храповик «доступно = 2»), классификатор реального стола (18), чистое ядро самопрогона (69),
  целостность сцен (через индекс Unity, 0,6 с), паузу/гейты.
- Правило TDD проекта: тесты ДО кода; после прогона тесты не менять (правится код). Ошибка в
  тесте — только с согласия владельца.

### Уровень 2 — интеграционные в редакторе (ПК-раскладка)
- E2E_PC (`KvE2eSettingsDiag.Run`): ≥29 проверок, [FAIL] = 0 — панель «Настройки», переключатель
  VR/MR, реестр команд.
- Гейт чистой консоли (`Tools/ci-console-check.ps1`) — предупреждения Unity как дефекты.

### Уровень 3 — мутационный контроль (негативный)
- 4 мутации (гистерезис IK, VR|MR ModeFromIndex, пауза без правила времени, половинный порог
  зазора): тесты ОБЯЗАНЫ падать на сломанном коде. «Зелёные на сломанном» = тесты ничего не
  проверяют = красный гейт.
- Правило: мутация меняет СМЫСЛ, не сигнатуру (иначе краснеет компиляция, а не тест).

### Уровень 4 — устройства (AR-планшет, VR/MR-шлем) — «боевые» проверки
| Проверка | Что доказывает | Стенд |
|---|---|---|
| E2E_AR | панель «Настройки» реально на экране (геометрия из журнала, не размер PNG); словари языков читаются на устройстве | планшет `91863b7e0983` |
| HEADSET | запуск без падений, [KvEnv], режим назван, XrMain загружена, НЕТ зависания на разрешении камеры | шлем `PA921DMGK4120784G` |
| UI_SWEEP | самопрогон интерфейса в 3 раскладках (AR/VR/MR): каждая кнопка нажата в живом uGUI, эффект доказан снимком состояния; «без эффекта» вне исключений = провал | оба |
| REAL_TABLE | (а) правила доказаны ≥15 тестами; (б) оба устройства напечатали ВЕРДИКТ С ЧИСЛАМИ («стол найден · площадь … · высота …» / «пол (не стол)» / «разметки нет — что делать») | оба |

Честные границы этих проверок фиксируются в выводе гейта (что именно НЕ подтверждено машинно и
требует человека) — умолчание границы запрещено.

### Уровень 5 — живой показ (за владельцем)
Машинно не проверяется и остаётся человеку: читаемость текста в шлеме, эргономика, «красиво ли»,
реальная физика руки/контроллера. План показа: цепочка «робот скрыт до закрытия меню → выбор
места за правым зелёным лучом → B фиксирует» (журнальные строки `РОБОТ: скрыт до закрытия меню`
→ `ВЫБОР МЕСТА РОБОТА: режим включён` → `МЕСТО РОБОТА ЗАФИКСИРОВАНО … подтверждено B`).

## 3. Механизм приёмки и итерации

**Единственный вердикт** — `Tools/acceptance-gate.ps1`, 14 проверок:
GIT_ASSETS · SECRET · APK_NAMES · APK_FRESH · REPO_GUARDS · P4_3_RATCHET · UI_STUBS · EDITMODE ·
E2E_PC · MUTATION · E2E_AR · HEADSET · UI_SWEEP · REAL_TABLE.
Коды: 0 — всё зелёное; 1 — есть красное; 3 — счётчик повторов (один пункт красный 3 прогона
подряд → СТОП и отчёт владельцу, а не четвёртый круг).

**Итерационный цикл (регламент работы):**
```
┌────────────┐    ┌──────────────────┐    ┌──────────────────┐    ┌──────────────┐
│ Тестирование│ →  │ Формулирование   │ →  │ Правка           │ →  │ Тестирование │──┐
│ (прогон    │    │ плана/дефекта    │    │ (субагент-       │    │ (приёмка     │  │
│  гейта)    │    │ карточка с числом│    │  разработчик)    │    │  прогоном)   │  │
└────────────┘    └──────────────────┘    └──────────────────┘    └──────────────┘  │
      ▲                                                                              │
      └──────────────────────────────────────────────────────────────────────────────┘
```
1. **Тестирование.** Прогон гейта/уровней; каждый дефект — карточка с ЧИСЛОМ (строка журнала,
   счётчик, координата), а не описанием.
2. **План.** Дефект формулируется как: что сломано → как измерено → критерий закрытия (строка
   журнала/тест, который станет зелёным). Неразрешимое «по кругу» получает решение по существу,
   а не четвёртую попытку (прецедент: UI_SWEEP).
3. **Правка.** Правит субагент-разработчик по TDD (тест → код). Репозиторийные правила
   обязательны: MainScene.unity построчно; без новых пакетов; без удалений по пути из переменной;
   тесты после прогона не менять; P4_3 не растёт; .ps1 с кириллицей — с BOM.
4. **Тестирование (приёмка).** СВОЙ прогон. Сборка Roslyn и «у меня зелёный отчёт» не
   принимаются — финальное слово за Unity и устройствами.

**Устройства и стенды.**
- Шлем PICO 4 Ultra `PA921DMGK4120784G` (VR/MR). Занят пользователем в очках → приложение не
  запустится (`activity is being kept for the user`) — это состояние стенда, не дефект.
- Планшет Redmi `91863b7e0983` (AR). Android может убить приложение по памяти — прогон повторяется
  один раз; второе убийство подряд = результат.
- Перед прогонами: стол перед планшетом, поверхность перед шлемом (для REAL_TABLE);
  разметка комнаты PICO — обязательное условие MR-покрытия (без неё «мешей 0, разметки 0» —
  честный вердикт, а не дефект).
- Сборка APK — только в ASCII-пути `C:\KazistovVv_Build` (`Tools\xr-build-apk-ascii.ps1`,
  `-TimeoutMinutes 120`); после сборки кэш каналов ILPP чистится (гейт делает это сам).

**Известные ограничения (не дефекты, но проверяются каждый прогон):**
- Переключатель VR/MR на лету не поднимает MR-конвейер — режим применяется перезапуском
  (решение владельца — перезапуск; в журнале предупреждение).
- `KvCommands.Invoke` не перехватывает исключения обработчика — поведение закреплено тестом,
  решение за владельцем (карточка открыта).

  (закрывается в текущей итерации).
- Границы машинного: в шлеме панель/переключатель VR|MR подтверждаются только человеком
  (HEADSET явно это печатает).
