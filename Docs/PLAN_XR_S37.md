### Пункт 1. Модели (значки) контроллеров — варианта A

Новый компонент `KvXrControllerVisuals` (файл `Assets/_Project/01_Scripts/Xr/KvXrControllerVisuals.cs`),

| Что | Как |
|---|---|
| модель | `Resources.Load<GameObject>("Controller/PICO 4U R")` и `… L` (пакет SDK 1.4.1) |
| материал | ВСЕ материалы префаба заменяются нашим через `KvRenderPipelineShaders` → **розового не будет**; материалы SDK (шейдер `o_com_shader_code`, собранный под встроенный конвейер) не используются |
| поза | каждый кадр из `KvXrInputSource.TryRightPose/TryLeftPose`; **нулевая поза отвергается** проверкой `isTracked` (ловушка [F2]) |
| без двоения | ровно один экземпляр на руку, повторное создание невозможно (идемпотентно); при `isTracked = false` модель **скрывается**, а не висит в воздухе |
| без просадки | `Animator` префаба выключается, `Collider` удаляются (иначе модель руки перехватывает луч телепорта), слой = `Ignore Raycast`, тени выключены, материалы общие (не по экземпляру) |
| откат | если `Resources.Load` вернул `null` — собираются примитивы (цилиндр + кольцо + сфера) нашим материалом, и это **прямо пишется в журнал** |
| строка журнала | `[KvXr] ИКОНКИ КОНТРОЛЛЕРОВ: показано 2 · модель «меш PICO 4 Ultra (SDK)» · правая (…) · левая (…) · материал наш · аниматоров выключено N · коллайдеров убрано N` |
| доп. проверка без шлема | редакторный метод `KvXrS37Tools.VerifySdkControllerModels()`: что реально загрузилось, сколько мешей/рендереров, границы модели в метрах, какие шейдеры были у префаба |

### Пункт 2. Панель: радиус 0.100 м — настройка + опросы

| Что | Как |
|---|---|
| настройка | `KvXrSettings.Get/SetGroupPanelRadius()` (ключ `KazistovVv.XR.Panel.Radius`), диапазон **0.08…0.42 м**, по умолчанию **0.100 м** |
| иконка и просвет | считаются ОТ радиуса, чтобы не слипались: `просвет = clamp(0.22 × дуга/иконок, 8 мм, 12 мм)`, `иконка = дуга/иконок − просвет` → при R = 0.100 м: иконка **27 мм**, просвет **8.0 мм** (числа печатаются в журнал) |
| веер | радиус веера = максимум из (радиус групп, радиус для N иконок при иконке не меньше 24 мм) — иначе 14 иконок «Визуализации» слипнутся; **оба радиуса печатаются** в журнал |
| строка журнала | `панель групп: встала У КОНТРОЛЛЕРА (левая рука) · радиус 0.100 м · иконка 27 мм · просвет 8.0 мм · высота … · от глаз … · иконок 8 · развёрнута НА оператора` |
| опросы | 2–3 итерации «больше/меньше/норма»: значение читается из файла подстройки (см. ниже) и печатается в журнал при каждом изменении; итоговое значение записывается в отчёт и в настройку по умолчанию |
| старые API | сигнатуры `KvXrGroupPanelLayout.RadiusForCount/GroupOffsets/FanOffsets/IconSizeMeters` **не меняются** (их проверяют уже запускавшиеся тесты) — новые перегрузки добавляются рядом |

**Файл подстройки без пересборки** (новый `KvXrTuning`): `Application.persistentDataPath/kv_xr_tuning.txt`
(на шлеме — `/storage/emulated/0/Android/data/com.KazistovVv.app/files/kv_xr_tuning.txt`, кладётся
через `adb push`). Формат `ключ=значение`, строки `#` — комментарии. Перечитывается раз в 2 с.
Ключи: `panel.radius`, `panel.forward`, `panel.up`, `ray.hand`, `visuals.mode`, `gesture.enabled`.
Значения ограничиваются теми же границами, что и настройки. Каждое изменение — строка
`[KvXr] ПОДСТРОЙКА: панель.радиус=0.100 → применено (радиус 0.100 м, иконка 27 мм)`.
Это и есть механизм опросов: **одна сборка — 2–4 варианта радиуса**, без часов ожидания.

### Пункт 3. Луч — из правой руки, как настройка

| Что | Как |
|---|---|
| настройка | `KvXrSettings.Get/SetRayHand()`, ключ `KazistovVv.XR.Ray.Hand`, по умолчанию **правая**; диапазон — левая/правая; в файле подстройки — `ray.hand=right|left` |
| указатель | `KvXrUiPointer` берёт руку из настройки: поза указания, курок, грип и стик — **той же** руки; нажатие курком этой руки |
| проверка сторон | в строке наведения печатается сторона: `источник КОНТРОЛЛЕР (правая рука)`; отдельная строка при старте и при смене: `[KvXr] Указатель: луч из ПРАВОЙ руки (курок правой) · панель у ЛЕВОЙ руки · рука луча — настройка` |
| панель | остаётся у **левой** руки независимо от руки луча (два разных значения) |
| телепорт | локомоция переходит на ту же руку, что луч (иначе «курок нажимает два действия»); в покое по умолчанию — правая, как и было |

### Пункт 4. Отслеживание кистей

| Что | Как |
|---|---|
| пакет | `com.unity.xr.hands` **1.9.0** ставится штатным менеджером пакетов (`Client.Add`), в `manifest.json` появляется запись |
| фича | включается `HandTracking` (провайдер OpenXR из XR Hands) для **Android**; `PICOProjectSetting.isHandTracking = true` — тогда хук SDK дописывает в манифест `handtracking=1` и разрешение `com.picovr.permission.HAND_TRACKING` |

| достоверность | кисть показывается только при `isTracked` **и** непустой позе суставов (ловушка [F2]: «нулевая поза — ложное срабатывание»); при потере — скрывается |

| если рантайм не отдаст кисти | честно пишется `[KvXr] ОТСЛЕЖИВАНИЕ РУК: подсистема есть, поз нет — рантайм кисти не отдаёт` и в отчёте будет «не проверено/не поддерживается», а не «работает» |

### Пункт 5. Жесты (согласованный набор)

Новый `KvXrGestures` + чистая логика распознавания (проверяется тестами без шлема).
Все пороги — в долях размера ладони (масштаб не важен: [S3.7] — никаких «на глаз»).

| Жест | Условие | Действие | Строка журнала |
|---|---|---|---|
| **щипок** правой | расстояние «большой–указательный» ≤ 0.30 ширины ладони, удержание 0.15 с | нажатие иконки под лучом (то же, что курок) | `[KvXr] ЖЕСТ: «щипок» сработал · правая рука · нажата иконка «…»` |
| **раскрытая ладонь** любой | все 5 пальцев выпрямлены (кончик дальше от ладони, чем сгиб), удержание 0.40 с | показать/скрыть панель | `[KvXr] ЖЕСТ: «раскрытая ладонь» сработал · левая рука · панель скрыта` |
| **указательный палец** правой | указательный выпрямлен, средний/безымянный/мизинец согнуты, удержание 0.40 с | следующая группа (после последней — снова иконки групп) | `[KvXr] ЖЕСТ: «указательный палец» сработал · правая рука · раскрыта группа «…»` |
| **щипок** левой | как щипок, удержание 0.15 с | закрыть веер (выход) | `[kvXr] ЖЕСТ: «щипок» сработал · левая рука · веер закрыт` |

Защита от ложных срабатываний: пауза **0.8 с** между срабатываниями одного жеста, жест
считается только по достоверной позе, смена жеста требует промежуточного «нейтрального»
положения (иначе жест не повторяется сам).

## 3. Чего в этой волне НЕ будет (честно, до начала)

Причина: панель уже жёстко прикреплена к левой руке (ваше же требование [S1.2]), перетаскивание потребовало бы режима «отклеить/приклеить» и добавило бы ложных срабатываний на удержании. Вместо него — выход из веера щипком левой руки. Если перетаскивание нужно, это отдельный пункт следующей волны.
2. **Длительный замер кадров под нагрузкой** — как и прежде, отдельным шагом (стартовые 90/90 снимаются).
3. **Ужатие текстур APK** — отложено вашим решением 18.10.2026.
4. **Смена подписи, запуск через adb, правка `MainScene.unity`, правка тестов** — не делается ([S3]).

## 8. Что считается успехом этой волны

Ровно [S2] задания: за первую минуту в шлеме видно оба контроллера на своих местах, панель у
левой руки меньшего радиуса с ловящимися иконками, луч из правой руки по умолчанию (и
переключается), кисти появляются при положенных контроллерах, согласованный жест срабатывает и
делает обещанное, кадры 90/90, ни розового, ни двоения, ни вращения, десктопный режим не тронут.
Каждый пункт — пара «строка журнала с числами + ваш взгляд в шлеме».
