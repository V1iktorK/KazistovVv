## 1. КОНТРОЛЛЕРЫ — ПРИЧИНА НАЙДЕНА, ОНА В НАШЕМ КОДЕ

### 1.1 Доказательства из потокового журнала шлема (`Logs/device-s35-stream.log`)

| Строка | Что из неё следует |
|---|---|
| 3412 `instance_info … "BD_controller_interaction":true` | расширение `XR_BD_controller_interaction` рантаймом **выдано**; путь `/interaction_profiles/bytedance/pico4s_controller` рантайму известен |
| 3657–3661 | три вызова постановки привязок: `khr/simple_controller`, `oculus/touch_controller`, `bytedance/pico4s_controller` |
| 3663 `xrSuggestInteractionProfileBindings: XR_ERROR_PATH_UNSUPPORTED` | отвергнут набор привязок — ошибка приходит сразу после нашего профиля ByteDance |
| 3665 `oxr_session_attach_action_sets … profiles.left path str = /interaction_profiles/khr/simple_controller` | рука остаётся на профиле Khronos → `устройств в системе 0` |

### 1.2 Механизм отказа (по исходнику пакета Unity)

`Library/PackageCache/com.unity.xr.openxr@05fb1a7d75d1/Runtime/input/OpenXRInput.cs:296`:

```
foreach (var userPath in binding.userPaths ?? deviceUserPaths)   // нет userPaths → ОБЕ руки
```

В нашем `KvPicoControllerProfile.cs` кнопки привязаны без `userPaths`, поэтому:

* `/input/a/click` (только правая) уходит и на **левую** руку;
* `/input/x/click`, `/input/y/…`, `/input/b/…` — крест-накрест;
* `/input/menu/click` — на **обе** руки.

Таких сочетаний «путь × рука» в профиле ByteDance нет, и по спецификации OpenXR
`xrSuggestInteractionProfileBindings` обязан вернуть `XR_ERROR_PATH_UNSUPPORTED`, **отклонив
весь набор привязок профиля**. Отсюда: ни позы, ни курка, ни стика, ни устройства ввода.

Официальный профиль (`Tools/_pico_ref/PICO4UltraControllerProfile.cs`) ставит `userPaths`
у каждой кнопки руки: `x/y/menu → leftHand`, `a/b → rightHand`. У нас этого не было.

### 1.3 Что делаем

1. `KvPicoControllerProfile.cs`: расставить `userPaths` по рукам ровно как в официальном профиле.
2. Добавить **правило проверки** `HandBindingViolation(path, userPaths)` и аудит
   `AuditHandBindings(out report)`, который проходит по настоящей карте действий.
   Это не «вторая проверка ради проверки»: правило ловит именно тот класс ошибки, из-за
   которого контроллеры не работают.
3. Строки журнала на устройстве:
   * `[KvXr] OpenXR: XR_BD_controller_interaction — доступно: да · включено: да`;
   * `[KvXr] OpenXR: привязки профиля проверены: N привязок, нарушений 0`;
   * `[KvXr] КОНТРОЛЛЕРЫ ПОЯВИЛИСЬ: правый … (trigger, devicePose, thumbstick, …)` (уже есть).

## 2. ПОДПИСЬ 0,5 с И ВЕЕР — ЛУЧ НЕ МОГ ПОПАСТЬ В ПАНЕЛЬ

### 2.1 Причина

`KvXrUiPointer` передаёт в `GraphicRaycaster` **мировую** точку, а uGUI считает её **экранными
пикселями**: `GraphicRaycaster.cs:184` → `currentEventCamera.ScreenPointToRay(eventPosition)`,
`:327` → `RectTransformUtility.RectangleContainsScreenPoint(...)`. Мировая точка `(0.4; 1.2; 0.5)`
превращается в луч через левый нижний угол экрана. Попадания были только по полноэкранному
«Blocker» десктопного канваса — потому и видели в журнале нажатия по невидимым кнопкам.

### 2.2 Что делаем

1. `KvXrGroupPanelLayout.TryHitIcon(...)` — чистая геометрия: пересечение луча с плоскостью
   панели и расстояние от центра иконки **в метрах**. Проверяется тестом без шлема.
2. `KvXrGroupPanel`: хранение действий иконок, `TryAim`, `SetHoverIndex`, `PressIndex`.
   Подпись и веер остаются там же, где были (порог 0,5 с и дуга 210° не меняются).
3. `KvXrUiPointer`: сначала геометрическое наведение на панель, затем луч/нажатие;
   наведение на десктопные канвасы в шлеме выключено (их там нет — сторож уже погасил).
4. Строки журнала (это и есть доказательство, которого требовал владелец):
   * `[KvXr] ПАНЕЛЬ: луч навёл иконку группы «…» — N.N см от центра, N.NN м от глаза`;
   * `[KvXr] ПОДПИСЬ: «…» через 0.50 с удержания`;
   * `[KvXr] ПАНЕЛЬ: НАЖАТИЕ «…» (уровень групп)`;
   * `[KvXr] ВЕЕР: группа «…» раскрыта — иконок N, дуга 210.0°, подписей нет`;
   * `[KvXr] ВЕЕР: закрыт`.

## 3. ПАНЕЛЬ У РУКИ

Основное положение — **у контроллера** (поза руки). Панель ставится перед контроллером по
направлению указания, разворачивается **на оператора** (мировой канвас виден с передней
стороны, [F2]). У пояса — только запасное положение, когда позы руки нет, и это прямо
называется в строке журнала:

* `[KvXr] панель групп: встала У КОНТРОЛЛЕРА (правая рука) · … м от глаза · высота … м · …° от взгляда · иконок 8`;
* `[KvXr] панель групп: позы контроллера НЕТ — панель у ПОЯСА …` (существующая).
