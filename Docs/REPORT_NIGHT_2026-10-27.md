### 4.3 НОВЫЙ ИНСТРУМЕНТ: `Assets/_Project/01_Scripts/Editor/KvUiShotDiag.cs`
Путь к снимку был неровным — 7 итераций, каждая со своим костылем (записано для потомков):
1. `ScreenCapture.CaptureScreenshot` **не работает в batchmode** (нет окна/swapchain — молча не пишет файл)
2. Выход через `ExitPlaymode()` **зависает** (§0.7.7 проекта) → выход напрямую `EditorApplication.Exit`
3. Вход в PlayMode после закрытия всех сцен **зависает** → паттерн DshDesktopUiDiag: `OpenScene(MainScene) → EnterPlaymode`
4. UI стартует в batchmode **скрытым** (0 видимых из 875 Graphic) → фаза `KazistovVvUIManager.SetUiVisible(true)` + ожидание 90 кадров проявления
5. `CanvasScaler` при `Screen=640x480` даёт схлопывание → ручной масштаб канваса по FOV
6. Рендер камеры → RenderTexture → `ReadPixels → EncodeToPNG` (паттерн DshScreenshotsDiag.Render)
7. Статические вызовы `Canvas.ForceUpdateCanvases()` (CS0176 при instance-вызове)

**Инструмент оставлен в проекте** (диагностический, `#if UNITY_EDITOR`, сцену не сохраняет).
Запуск: `Unity.exe -batchmode -projectPath <проект> -executeMethod KvUiShotDiag.Run`

### 4.4 Найдено попутно (magenta-фон на runtime_UI.png)
Диагностика: в **batch-PlayMode поднимается уровень качества 0 «High» с URP**
(`UniversalRenderPipelineAsset`), а материалы MainScene — HDRP → magenta.
Все попытки переключиться на HDRP-уровень (1/2/3) в batch-среде остаются URP.
**Это ограничение batch-среды, не приложения**: в живом редакторе сцена рендерится
корректно (те же 6 PNG сцен чистые, HDRP-контент на месте). На реальной сборке
платформа `StandaloneWindows64`/Android со своим пресетом — явление не воспроизводится.

Также в логе: `KvRenderPipelineTools.InspectScene has invalid parameters` — метод меню
зарегистрирован с сигнатурой, которую Unity не принимает (мелкий дефект, 2 строки в лог).
