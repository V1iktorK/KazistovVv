## 1. ГЛАВНОЕ ОТКРЫТИЕ: ИНСТРУМЕНТ ПРОВЕРКИ ОШИБАЕТСЯ ЧАЩЕ КОДА

За ночь я **одиннадцать раз** (по журналу и отчёту) обнаружил, что проверка — моя же — расходилась
с реальностью. Не код, а **проверка**. Каждый раз это выглядело убедительно и каждый раз было
неправдой. Вот перечень, чтобы не повторять:

| Что случилось | Урок |
|---|---|
| Тест гигиены объявил 8 папок «не игнорируемыми», хотя `git ls-files` показывал обратное | разбор `.gitignore` не понимал классы `[Ll]` (E-19) |
| Проверка целостности сцен нашла **11 потерянных скриптов**, которых не было | искала только в `Assets`, а скрипты в пакетах (E-20) |
| Сторож NaN объявил нарушителями обычную геометрию сцены | область проверки не совпадала с областью, где класс возможен |
| Утечка объявила `KvBindings.cs` «удалённым» | файл в другой папке (`06_KazistovVv_UI`) |
| Тест манифеста записи падал **трижды** по трём разным причинам разбора | границы метода по строкам не работают |
| Отчёт говорил «51 коммит» при 90 | документ устаревает молча |

### Правило, которое я вывел и применил

> **У каждого сторожа, читающего текст или файлы, должна быть САМОПРОВЕРКА: «а разбор вообще
> что-то нашёл?»**

Без неё проверка либо зеленеет по определению (E-16: 13 тестов-декораций), либо краснеет по
ошибке разбора (E-19) — и в обоих случаях непонятно, что именно проверено.

### Частный случай: разбор C#-кода

За ночь я **пять раз** спотыкался на разборе методов регулярками. Работает только один способ:

```csharp
// Границы метода считаются ПО ГЛУБИНЕ СКОБОК.
int open = text.IndexOf('{', start);
int depth = 1, at = open + 1;
while (at < text.Length && depth > 0) { if (text[at]=='{') depth++; else if (text[at]=='}') depth--; at++; }
```

Регулярка `\([^)]*\)` обрывается на вложенных скобках. Поиск по подстроке находит **вызов** метода
раньше объявления. Строка из одних `}` — это конец `if`, а не метода.

## 2. ВТОРОЕ ОТКРЫТИЕ: ЛОЖНОЕ «ДА» ОПАСНЕЕ ОТКАЗА

Половина найденных дефектов — это код, который **говорил «хорошо», когда было плохо**:

| Дефект | Что видел оператор |
|---|---|
| `SafetyGate.Velocity` не выставлялась никогда | в списке причин есть «превышение скорости», но скорость никто не проверял |
| `Play()` не снимал паузу | «нажал ПУСК — ничего не происходит», без ошибки |
| На паузе контроль зазора выключался | после аварии робот стоит без проверок |
| `MrActive` верил тумблеру, а не железу | стенды погашены, стол «поставлен» — **пустая комната** |
| Строка журнала печатала константу 1.00 | замер масштаба в MR подтверждал сам себя |

**Правило:** если функция вернула успех, состояние обязано измениться. Если в списке причин есть
строка — должна быть и проверка, которая её выставляет.

## 3. ТРЕТЬЕ: СРАВНЕНИЕ С NaN ВСЕГДА ЛОЖНО (E-21)

```csharp
if (distance < 0.01f) return false;   // для NaN НЕ срабатывает
if (distance > 3f)    return false;   // для NaN НЕ срабатывает
```

Выглядит как защита от мусора. **Пропускает худший случай.**

Найдено **восемь** мест. Последствия: контроллер **исчезал из мира** (Unity не рисует объекты с
NaN), жест молча не срабатывал, панель нажималась сама, GJK объявлял ложное столкновение, окно
уезжало в бесконечность, робот оставался в позе, которой никто не просил.

Откуда NaN: **не из плохого кода, а из железа** — деление на ноль при потере отслеживания.

**Правило:** любая проверка расстояния начинается с отсева нечисла.

## 4. ЧЕТВЁРТОЕ: НЕЗАПИСАННОЕ ПРАВИЛО = ДВА ДЕФЕКТА (E-22)

Два дефекта паузы, найденные с разницей в раунд, оказались **одной причиной**: никто не сформулировал,
что такое пауза.

Пока правила нет, каждый метод решает за себя — и оба решения выглядят разумными по отдельности.

**Правило:** если два класса делают похожее, у них обязан быть ОДИН записанный контракт и тест на
согласованность.

## 5. ЧТО ЭТО ЗНАЧИТ ДЛЯ СУББОТЫ

### Что делать в первую очередь

1. **Собрать, надеть шлем, прочитать две строки** — `Docs/ПЛАН_НА_СУББОТУ_MR.md`, шаг 1.3.
2. **Решить про пропорцию стола** (10:7 против 3:2) — это не код, это выбор.
3. **Проверить стенды**: в VR видны, в MR скрыты.

### Чего не делать

- **Не верить отчёту больше, чем журналу.** Если план говорит одно, а журнал другое — прав журнал.
- **Не «чинить» то, что кажется сломанным, без проверки числами.** За ночь я дважды почти начал
  исправлять исправное.
- **Не считать «зелёный прогон» доказательством.** Он доказывает только то, что проверки смогли
  упасть и не упали.

### Что осталось непроверенным и почему

| Что | Почему |
|---|---|
| Проба сквозного вида на шлеме | нужен шлем |
| Масштаб стола в MR | нужен замер на устройстве |
| AR на телефоне | код есть, устройство не проверялось |
