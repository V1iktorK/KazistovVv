5. Собраны **оба** APK, и файлы лежат под правильными именами со **свежим** временем:
   `Builds\KazistovVv-VR-vulkan.apk` (шлем) и `Builds\KazistovVv-AR-gles3.apk` (планшет).

### P1 — ПРЕДОХРАНИТЕЛИ И НАСТРОЙКИ СООБЩАЮТ НЕ ТО, ЧТО ЕСТЬ

#### P1-1 · Настройки интерфейса не сохраняются на диск
`06_KazistovVv_UI/03_Scripts/Core/KvSettings.cs:224,229` — оба хелпера `Save(string,int)` и
`Save(string,float)` вызывают только `PlayerPrefs.Set*` **без `PlayerPrefs.Save()`**, а doc-комментарий
класса обещает «переживают перезапуск». Затронуто: масштаб, плотность, размер шрифта, контраст,
схема для дальтоников, клавиатурная навигация, HUD геймпада.
**Сделать:** `PlayerPrefs.Save()` в общем `Save`.
Родственное: `Zones/KvCommandPalette.cs` (история команд) и `Core/KvLayoutStore.cs` — `Save()` без
`Flush()`, а сам `Flush()` — `try { PlayerPrefs.Save(); } catch { }` **с пустым catch**; при этом
`SavePanelState` в менеджере `Flush()` не зовёт.
**Проверка:** тест «после `KvSettings.UiScale = 1.2` ключ есть и `PlayerPrefs.Save` вызван» —
проще: сравнить, что значения читаются после `KvSettings.Reload()`.

#### P1-2 · Половинчатое сохранение настроек шлема
`01_Scripts/Xr/KvXrSettings.cs` — `SetModeIndex` и `ToggleMoveMode` зовут `PlayerPrefs.Save()`, а

`SetTeleportDistance`, `SetPanelDistance`, `SetWorldScale`, `SetOperatorHeight`, `SetSecondaryRay`,
`SetRayHand`, `SetGesturesEnabled` — нет. Два правила для одного хранилища.
**Сделать:** один приватный `Save()` с `PlayerPrefs.Save()` для всех сеттеров.

#### P1-3 · «Число рядов тулбара» сохраняется, но не применяется
`KvSettingsView.cs` пишет `KvSettings.ToolbarRows` (clamp 1…6); менеджер передаёт в

#### P1-4 · Геттер пишет в `PlayerPrefs` и меняет глобальный флаг
`01_Scripts/Features/KvCollisionOptimizer.cs:112` — геттер `Enabled` зовёт `Load()`, а `Load()`

Чтение свойства откатывает глобальный реестр прокси столкновений — то есть **предохранитель зазоров**.
**Сделать:** геттер — только `return enabled;`; загрузка один раз в `Bind`/`Awake`.

#### P1-5 · Два разных «масштаба мира», и ни один не применяется к геометрии
`01_Scripts/Xr/KvXrPlatformMode.cs:60,66` — `DefaultWorldScale = 1.0f` и `WorldScale`, документирован
как «ЕДИНСТВЕННОЕ МЕСТО», всегда 1.0, попадает только в строку лога.
`01_Scripts/Xr/KvXrSettings.cs:77,447` — `GetWorldScale()` (0.1…1) → `BuildRigConfig()` →
`KvXrRigConfig.worldScale`, читается **только** в `Describe()`, к `transform.localScale` не
применяется никогда.
**Почему критично:** в MR масштаб — условие работы. Журнал печатает «мир 0.50×», а стол и робот
остаются 1:1 — наладчик делает замер по журналу и подтверждает ложь.
**Сделать:** один источник (`KvXrSettings.GetWorldScale`), реально применять к корню мира, второй
удалить; в журнал печатать **фактически применённое** значение.

#### P1-6 · Калибровка сохраняется и НИКОГДА не восстанавливается
`01_Scripts/Spatial/CalibrationTool.cs` — `PlayerPrefs.SetFloat("CalX"…)` + `Save()`.
**Замерено: записей ключей `Cal*` — 7, чтений — 0** по всему проекту. Смысл калибровки —
«после перезапуска виртуальный робот совпадает с реальным»; совпадения нет, и никто не узнает.
Там же: `virtualRobotBase.rotation = rotOffset * virtualRobotBase.rotation;` накладывает поворот на
**текущий** (вторая калибровка накапливает перекос), а позиция задаётся абсолютно;
`Instantiate(calibrationPointPrefab, …)` — результат отбрасывается, объект не уничтожается;
`calibrationUI.SetActive(...)` без проверки на null.
**Сделать:** `LoadCalibration()` в `Start`; поворот хранить один раз; маркеры уничтожать; проверки null.

#### P1-7 · «Пространственный якорь» — это мировые координаты в `PlayerPrefs`
`01_Scripts/Spatial/SpatialAnchorManager.cs` — сохраняет `AnchorX/Y/Z`/`AnchorQx…` в мировых
координатах **сцены**, никакого `ARAnchor`/`XROrigin` не создаёт. `void Awake() => Instance = this;`
без сброса в `OnDestroy`, `Instance` не читается нигде.
**Почему критично:** начало отсчёта трекинга задаёт шлем и меняет при перецентровке/перезапуске —
«восстановленный» робот окажется не на своём столе.
**Сделать:** хранить позу относительно `XROrigin`/трекингового пространства (или настоящий
`ARAnchor`); `Instance` убрать.

#### P1-8 · Статический `SettingsData.Instance` + молчаливый откат скорости робота на 1.0
`01_Scripts/UI/SettingsData.cs:6` — `public static SettingsData Instance`, выставляется в `OnEnable`,
без сброса в `OnDisable/OnDestroy`. Читатели: `SCARAController.cs`, `SixAxisController.cs` — при
`Instance == null` молча берут `robotSpeed = 1f`: оператор поставил 0.2 → робот едет в 5 раз быстрее,
в журнале ничего. `SettingsMenu.ResetToDefaults` создаёт `CreateInstance<SettingsData>()`, чей
`OnEnable` **перехватит** `Instance`, и объект не уничтожается.
**Сделать:** убрать статическое поле, получать ассет через `SerializeField`; отсутствие логировать.

#### P1-9 · Гистерезис выбора ветви IK инвертирован
`01_Scripts/Trajectory/PostureSelector.cs:120` —
`if (foundLocked && bestCost > lockedCost * (1.0 - hysteresis)) return best;`
`best` — глобальный минимум, значит `bestCost <= lockedCost`, поэтому условие истинно ровно при
**малом** выигрыше: переключение происходит именно тогда, когда не нужно, а при явном улучшении ветвь
удерживается.
**Сделать:** `if (bestCost < lockedCost * (1.0 - hysteresis))`. Тест на оба случая.

#### P1-10 · `active.Times` разыменовывается без проверки
`01_Scripts/Trajectory/TrajectoryExecutor.cs` — `float[] times = active.Times;` затем `times.Length`.
`Play()` и `SafetyGate.Approve` проверяют только `Path`; `MotionTiming.RescaleToSpeed` при
`Times == null` просто выходит, оставляя поле пустым → `NullReferenceException` в `Update`.
**Сделать:** отклонять план с `Times == null || Times.Length != Path.Length` в `Play` **и** в
`SafetyGate.Approve`, с понятным сообщением.

#### P1-11 · Кэш оракула достижимости: одно поле `cacheTime` на все записи
