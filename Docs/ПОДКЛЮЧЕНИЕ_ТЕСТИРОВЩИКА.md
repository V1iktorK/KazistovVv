# ЧАСТЬ 1. ЧТО ДЕЛАЕТ ВЛАДЕЛЕЦ (вы)

Прежде чем тестировщик начнёт, ему нужно **выдать доступ**. Выберите ОДИН путь.

## Путь А (рекомендую): GitHub — проект уже там

Проект уже лежит на GitHub, проверено клонирование (2290 файлов, 89 МБ).

1. Откройте в браузере: `https://github.com/V1iktorK/KazistovVv`
2. Вверху справа нажмите **Settings** (⚙).
3. В левом меню выберите **Collaborators** (в разделе «Access»).
4. Нажмите зелёную кнопку **Add people**.
5. В поле введите **email** или **GitHub-логин** тестировщика.
6. В выпадающем списке роли выберите **Read** (ему достаточно читать).
7. Нажмите **Add <имя> to this repository**.
8. Он получит письмо — пусть примет приглашение.

**Всё.** Больше ничего настраивать не надо.

## Путь Б: Unity Cloud (Unity Version Control)

Интерфейс Unity Cloud periodically меняется, поэтому шаги могут называться чуть иначе —
ориентируйтесь по смыслу.

1. Откройте `https://cloud.unity.com` и войдите **своим** аккаунтом Unity.
2. Вверху выберите вашу **организацию** (Organizations).
3. В левом меню найдите **DevOps** → **Version Control** (может называться «Unity Version Control»
   или «Plastic SCM»).
4. Если репозитория ещё нет — нажмите **Create repository**, задайте имя (например `KazistovVv`).
5. Откройте созданный репозиторий → вкладка **Members** (или **Users**).
6. Нажмите **Invite member** / **Add member**.
7. Введите **email** тестировщика, роль — **Viewer** (только чтение).
8. Отправьте приглашение.

**ВАЖНО:** чтобы залить проект в Unity Cloud, нужен пакет `Version Control`
(`com.unity.collab-proxy`). В проекте его **нет**. Если хотите этот путь — скажите, я добавлю.

**Мой совет: используйте Путь А (GitHub).** Он уже работает, проверен, и не требует ни пакетов,
ни настройки.

# ЧАСТЬ 2. ЧТО ДЕЛАЕТ ТЕСТИРОВЩИК

## Шаг 1. Установить Unity Hub

1. Откройте в браузере: `https://unity.com/download`
2. Нажмите большую кнопку **Download for Windows** (или для вашей ОС).
3. Откроется страница загрузки — файл `UnityHubSetup.exe` скачается автоматически.
4. Запустите скачанный файл (двойной клик).
5. В окне установки нажмите **I agree** (принять лицензию).
6. Нажмите **Install**.
7. Дождитесь окончания, нажмите **Finish**.
8. Запустите **Unity Hub** (ярлык на рабочем столе или в меню «Пуск»).

## Шаг 2. Войти в аккаунт Unity

1. В Unity Hub слева нажмите **Sign in** (или иконку профиля в левом нижнем углу).
2. Откроется браузер — войдите **своим** аккаунтом Unity (или создайте: **Create account**).
3. Браузер спросит разрешение — нажмите **Allow** / **Разрешить**.
4. Вернитесь в Unity Hub — вы увидите своё имя внизу слева.
5. **Если аккаунта нет:** на `id.unity.com` нажмите **Create a Unity ID**, заполните почту, пароль,
   имя. Лицензия **Personal бесплатна** — её Unity Hub предложит активировать сам, нажмите
   **Get a free personal license** → **Agree and get personal edition license**.

## Шаг 3. Установить ТУ ЖЕ версию Unity — 6000.5.6f1

Это критично: другая версия может не открыть проект.

1. В Unity Hub слева нажмите **Installs** (иконка с квадратом).
2. Нажмите синюю кнопку **Install Editor** (справа вверху).
3. Откроется окно со списком версий. Найдите вкладку **Archive** (вверху окна).
4. В списке найдите **6000.5.6f1**.
   - Если не видно — в строке поиска введите `6000.5.6f1`.
5. Рядом с версией нажмите **Install**.
6. Откроется окно выбора модулей. **Обязательно поставьте галочки:**
   - ✅ **Android Build Support**
     - ✅ **Android SDK & NDK Tools** (вложенная галочка)
     - ✅ **OpenJDK** (вложенная галочка)
   - ✅ **Windows Build Support (IL2CPP)** — если будете смотреть проект на ПК

   **Для Quest 3 нужен именно Android Build Support с SDK/NDK/OpenJDK.**
7. Нажмите **Continue** (или **Install**).
8. Примите лицензию: **I agree** → **Install**.
9. Дождитесь загрузки. **Это долго — 20–60 минут**, зависит от интернета. Не закрывайте окно.

## Шаг 4. Получить проект

### Если владелец выбрал GitHub (Путь А)

**Вариант 1 — через GitHub Desktop (проще для не-программиста):**

1. Скачайте **GitHub Desktop**: `https://desktop.github.com` → **Download for Windows**.
2. Установите (двойной клик → далее → Install).
3. Запустите, войдите своим GitHub-аккаунтом: **Sign in to GitHub.com**.
4. В меню сверху: **File → Clone repository…**
5. Откроется окно. Выберите вкладку **GitHub.com**.
6. В списке найдите **V1iktorK/KazistovVv**.
   - Если не видно — нажмите **Refresh** (круглая стрелка).
7. В поле **Local path** впишите путь **БЕЗ РУССКИХ БУКВ**, например:
   ```
   C:\KazistovVv_Test
   ```
8. Нажмите **Clone**.
9. Дождитесь окончания — около 89 МБ.

**Вариант 2 — просто скачать архивом (если git не нужен):**

1. Откройте `https://github.com/V1iktorK/KazistovVv`
2. Нажмите зелёную кнопку **Code** (справа вверху).
3. В выпадающем окне выберите вкладку **Local**.
4. Нажмите **Download ZIP**.
5. Распакуйте архив в `C:\KazistovVv_Test`
   - ⚠ **Внутри архива будет папка `KazistovVv-main`** — убедитесь, что путь получился
     `C:\KazistovVv_Test` (в нём лежат папки `Assets`, `Packages`, `ProjectSettings`), а не
     `C:\KazistovVv_Test\KazistovVv-main\KazistovVv-main`.

**Проверка:** откройте `C:\KazistovVv_Test` — внутри должны быть папки **Assets**, **Packages**,
**ProjectSettings**, **Tools**, **Docs**.

### Если владелец выбрал Unity Cloud (Путь Б)

1. Примите приглашение из письма.
2. В Unity Hub слева нажмите **Projects**.
3. Нажмите стрелку рядом с **Add** → **Add project from Unity Version Control**.
4. Войдите аккаунтом Unity (тем же, куда пришло приглашение).
5. Выберите организацию → репозиторий → **Clone**.
6. Путь снова **БЕЗ РУССКИХ БУКВ**: `C:\KazistovVv_Test`.

## Шаг 5. Открыть проект в Unity

1. В Unity Hub слева нажмите **Projects**.
2. Нажмите кнопку **Add** (справа вверху) → **Add project from disk**.
3. В окне выбора папки перейдите в `C:\KazistovVv_Test` и выберите её.
4. Нажмите **Select Folder**.
5. Проект появится в списке. Рядом должна стоять версия **6000.5.6f1**.
   - Если версия другая — нажмите на выпадающий список версии справа от проекта и выберите
     6000.5.6f1.
6. Нажмите на название проекта, чтобы открыть.

**Первый запуск — долгий.** Unity импортирует все пакеты и ассеты: **20–60 минут**. Так и должно
быть. Не закрывайте. Внизу справа будет полоска прогресса.

**Когда откроется:** вы увидите редактор Unity. Если появится окно с предложением войти в
безопасный режим (Safe Mode) — **не входите**, а покажите текст ошибки.

## Шаг 6. Проверить, что всё на месте

1. Вверху меню: **Window → Package Manager**.
2. В открывшемся окне слева выберите **In Project** (вверху слева выпадающий список).
3. В списке должны быть: `XR Plug-in Management`, `OpenXR Plugin`, `XR Hands`, `AR Foundation`,
   `XR Interaction Toolkit`.
4. Если чего-то нет — Unity докачает сам, подождите.

5. Проверка сцены: в окне **Project** (внизу) откройте **Assets → _Project → 00_Scenes**.
6. Двойной клик по **XrMain** — сцена загрузится.

## Шаг 7. Собрать APK для Quest 3

**Пакет поддержки Meta УЖЕ В ПРОЕКТЕ** (`com.unity.xr.meta-openxr` 2.4.1) — добавлять ничего
не нужно. Проверить можно так: **Window → Package Manager → In Project** → в списке должен быть
**Unity OpenXR Meta**.

**Осталось включить профили (это делает тестировщик один раз):**

1. **Edit → Project Settings**
2. В левом списке выберите **XR Plug-in Management**
3. Сверху выберите вкладку с иконкой **робота Android** (Android-платформа)
4. Поставьте галочку **OpenXR**
5. Разверните **OpenXR** (стрелка слева) → подпункт **Interaction Profiles**
6. Нажмите **+** и добавьте: **Meta Quest Touch Plus Controller Profile**
   - PICO-профиль **не удаляйте** — оба должны быть в списке
7. Вернитесь в **XR Plug-in Management → Android** и убедитесь, что стоит галочка
   **Meta Quest Support**

**Сборка:**

1. **File → Build Profiles** (в старых версиях — **Build Settings**)
2. В списке слева выберите **Android** и нажмите **Switch Platform**
   - Долго — 5–15 минут
3. **Edit → Project Settings → Player → Publishing Settings**
4. Снимите галочку **Custom Keystore** (чтобы собралось с отладочным ключом)
   - ⚠ **Важно:** не просите ключ владельца. Для теста достаточно отладочного.
5. **File → Build Profiles** → нажмите **Build**
6. Выберите папку `C:\KazistovVv_Test\Builds`, имя файла `KazistovVv.apk`
7. Нажмите **Save** и ждите **20–40 минут**

## Шаг 8. Установить на Quest 3

1. Наденьте шлем и включите.
2. Подключите его кабелем к компьютеру.
3. В шлеме появится запрос **«Разрешить отладку по USB?»** — нажмите **Разрешить** (Always allow).
4. **Если запрос не появился:** в шлеме откройте **Настройки → Система → Для разработчиков** и
   включите **Отладка по USB**.
   - Если пункта «Для разработчиков» нет: **Настройки → О телефоне/О системе** → 7 раз нажмите на
     **Номер сборки**.
5. На компьютере скачайте **SideQuest**: `https://sidequestvr.com/setup-howto`
6. Установите и запустите SideQuest — он сам скачает нужные компоненты.
7. В SideQuest нажмите иконку **установить APK** (стрелка вверх в панели сверху).
8. Выберите ваш `KazistovVv.apk`.
9. Дождитесь установки.
10. В шлеме: **Библиотека → Неизвестные источники** (Unknown Sources) → запустите **KazistovVv**.

**Или без SideQuest, через командную строку:**

```
adb install -r "C:\KazistovVv_Test\Builds\KazistovVv.apk"
```

# ЧАСТЬ 4. ЧЕГО НЕ ДЕЛАТЬ

| Нельзя | Почему |
|---|---|
| **Менять версию Unity** | проект откроется с ошибками |
| **Класть проект в путь с русскими буквами** | сборка APK упадёт |
| **Просить ключ подписи** | он не нужен, для теста хватает отладочного |
| **Удалять папку `Library`** | это кэш, после удаления импорт займёт час |
| **Коммитить папку `Library`** | она весит гигабайты и не должна попадать в репозиторий |
| **Менять `Packages/manifest.json` вручную** | сломается набор пакетов; делать через Package Manager |

# ЧАСТЬ 5. ЕСЛИ ЧТО-ТО СЛОМАЛОСЬ

| Симптом | Что делать |
|---|---|
| **«Project was last saved with a different version»** | нажать **Continue** и открыть; если сыпет ошибками — установить точно 6000.5.6f1 |
| **Ошибки компиляции при первом открытии** | подождать 5 минут — Unity ещё импортирует; если остались, показать текст |
| **Сборка падает: «No keystore passwords»** | снять галочку **Custom Keystore** в Player → Publishing Settings |
| **Сборка падает: «Invalid project path … non-ASCII»** | перенести проект в `C:\KazistovVv_Test` (без русских букв) |
| **Сборка падает: «Could not find class prefab»** | это кэш Gradle в папке с кириллицей; см. ниже |
| **APK не ставится на шлем** | включить «Отладка по USB» и разрешить компьютер |
| **Шлем не виден в SideQuest** | переподключить кабель, нажать «Разрешить» в шлеме |

**Про ошибку Gradle с кириллицей** (редкая, но встретилась у нас):

Если в имени домашней папки пользователя есть русские буквы, Gradle ломается. Лечится так:
в переменных среды Windows создать переменную `GRADLE_USER_HOME` со значением `C:\GradleHome`
(путь без русских букв). Папку создаст Gradle сам.

# ЧАСТЬ 6. ЧТО ПРИСЛАТЬ ВЛАДЕЛЬЦУ

После теста пришлите три вещи:

1. **Журнал**: файл `quest-log.txt` (команда выше).
2. **Заполненный чек-лист** из Части 3.
3. **Если что-то не работает** — короткое видео экрана шлема (запись через SideQuest или кнопку
   записи в шлеме). Одно видео лучше десяти описаний.

**И главное:** если что-то выглядит странно — напишите **что именно** вы видите, своими словами.
«Всё крутится» и «панель уехала вправо» — это два совершенно разных дефекта.
