# Участие в проекте / Contributing

**KazistovVv — проприетарный проект.** Внешние вклады (pull request, патчи,
фрагменты кода) **не принимаются** без предварительного письменного соглашения
с правообладателями. Отправляя код без такого соглашения, вы не создаёте
оснований для его включения в проект.

**KazistovVv is a proprietary project.** External contributions (pull requests, patches,
code snippets) are **not accepted** without a prior written agreement with the Rights
Holders. Sending code without such an agreement does not create any basis for including
it in the project.

## 1. Что можно сделать без договора / Allowed without an agreement

| Действие / Action | Разрешено / Allowed |
|---|---|
| Читать код и документацию / Read code and docs | да / yes |
| Клонировать и собирать неизменённую копию для оценки / Clone and build an unmodified copy for evaluation | да / yes |
| Сообщить о дефекте письмом / Report a defect by email | да / yes |
| Сообщить об уязвимости / Report a vulnerability | да / yes — см. [`SECURITY.md`](SECURITY.md) |
| Предложить функцию / Suggest a feature | да, письмом / yes, by email |
| Открыть pull request с кодом / Open a code pull request | **нет / no** |
| Форк и публикация изменённой версии / Fork and publish a modified version | **нет / no** |

Письма о дефектах и предложения рассматриваются без гарантии срока и без
обязательства реализовать.

### Как полезно оформить сообщение о дефекте

1. Версия: коммит, ветка, `bundleVersion` (`ProjectSettings/ProjectSettings.asset`).
2. Платформа: Windows / Android / шлем (модель), версия Unity.
3. Что ожидалось и что произошло.
4. Шаги воспроизведения — минимальные, начиная с открытия `MainScene`.
5. Лог консоли (**без** ключей, токенов и персональных данных).

## 2. Правила для внутренней разработки / Internal development rules

Раздел для тех, у кого есть доступ к разработке. Это инварианты проекта: их
нарушение — дефект, даже если код «работает».

### 2.1 Обязательные инварианты

| Инвариант | Почему |
|---|---|
| **Любое движение — только через `MotionExecutor`** под проверкой `SafetyGate` | единственная точка, где контролируются лимиты, коллизии и зоны |
| **`TrajectoryFlowController` — точка правды о роботе** | состояние потока и выбранный робот не дублируются в других местах |
| **Никакого ИИ в контуре движения** | конвейер детерминирован и воспроизводим по журналу действий |
| **Интерфейс строится кодом в рантайме** | сцена `MainScene` не переделывается под UI |
| **Материалы, создаваемые кодом, — только через `KvRenderPipelineShaders`** | проект живёт на двух конвейерах (URP и HDRP) одновременно |
| **Пути в `Assets/` — только ASCII** | сборка Android падает на кириллице в путях |
| **Данные, читаемые без перекомпиляции, — в `Assets/StreamingAssets/`** | локализация и настройки правятся без пересборки |
| **Локализация — все 7 языков одновременно** | ключ без перевода в любом из словарей считается дефектом |

### 2.2 Перед коммитом

1. `dotnet build` — без ошибок и предупреждений C#.
2. Гейт «чистой консоли»: **0 error / 0 warning / 0 exception** (скрипты в `Tools/`).
3. EditMode-прогон — зелёный; упавшие тесты не «отключаются», а разбираются.
4. `Tools/repo-guards.ps1` — артефакты сборки не в индексе, нет `.meta` без ассета,
   нет не-ASCII путей, ключи подписи не в git.
5. В `Assets/` не должно быть посторонних файлов — Unity импортирует их как ассеты.

### 2.3 Ветки и коммиты

- Рабочая ветка — `Develop`; `main` — публикуемое состояние.
- Сообщение коммита — по-русски, с указанием пункта задания (`P4-16:`, `R6-1:` и т. п.),
  если коммит закрывает пункт.
- Один коммит — одна причина изменения.
- Сгенерированные каталоги (`Library/`, `Temp/`, `obj/`, `Logs/`, `Builds/`,
  `UserSettings/`) **никогда** не коммитятся.

### 2.4 Документация как часть работы

Журнал проекта — [`PROJECT_CONTEXT.md`](PROJECT_CONTEXT.md). Значимая сессия
завершается разделом в нём и, при необходимости, отчётом в `Docs/`.
Числа в документации должны быть **измеренными**, а не оценочными.

## 3. Лицензионная гигиена / License hygiene

- Не добавляйте в репозиторий сторонний код, модели, текстуры и шрифты без проверки
  их лицензии — см. [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).
- Не добавляйте код с лицензиями GPL / AGPL и иными копилефт-лицензиями: они
  несовместимы с проприетарной моделью распространения.
- Не коммитьте ключи подписи, токены, сертификаты и личные данные.
- Тесты и примеры не должны содержать данные реальных заказчиков.
