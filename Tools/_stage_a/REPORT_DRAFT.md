## 3. A1. Сборка APK №1: чем она на самом деле была занята

Сборка шейдеров — вот что заняло всё время (числа из `Logs\xr-build-apk-s30.log`):

| Показатель | Значение |
|---|---|
| Шейдеров в сборке | **111** (`Compiling shader …`), собрано 110 |
| Записей о проходах | 196 |
| Вариантов скомпилировано в завершённых проходах | **29 602** |
| Вариантов в проходе, который шёл на момент замера | 43 892 (из 46 080) |
| Оценка всего вариантов на сборку | **~122 000** |
| Самый дорогой проход | terrain `WavingDoublePass` / `ForwardLit`: 13 824 варианта, **18 836 с** |
| Второй по цене | `URP/FinalPost`: 4 прохода × 2560 = 10 240 вариантов, 8127 + 8104 + 7789 + 6260 с |
| Узкое место в конце | `URP/UberPost`: **46 080 вариантов на каждый из двух проходов** (`UberPost`, `UberPostXR`) |

**Почему вариантов столько (карточка Б2, точные числа):**

```
Compiling shader "Hidden/Universal Render Pipeline/UberPost"
  Pass "UberPost"    Full variant space: 92.160 → фильтрация 23.040 → встроенное отсечение 46.080
  Pass "UberPostXR"  Full variant space: 92.160 → фильтрация 23.040 → встроенное отсечение 46.080
```

Отсечение не уменьшает набор, а **удваивает** его. Один шейдер постобработки стоит 92 160
вариантов; сборка — ~122 000. Скорость на четырёх ядрах Intel N97: 2,6–11 с на вариант.

**Вывод для проекта:** пока это не исправлено, КАЖДАЯ сборка APK стоит сутки и больше.
Это делает §31–§34 (четыре сессии приёмки на устройстве) невыполнимыми по времени.

## 4. A2. Дефект возврата тестов — и второй дефект рядом

Правка вынесла парковку и возврат из `BuildAndroidApk` в методы, работающие только с путями
(`System.IO`): саму сборку тестом не проверить, а правила парковки и возврата — можно.
Порядок как в проекте принято: **тесты написаны первыми и падали** (красная точка), затем
вылечен код (зелёная точка).

| Дефект | В чём состоял | Как вылечен |
|---|---|---|
| **A2** (заданный) | возврат выполнялся только если папки в `Assets` НЕТ; Unity пересоздаёт пустую папку (её `.meta` остаётся) → 23 файла тестов остались бы в `Temp` навсегда, **молча** | разбираются четыре случая: парковки нет / папки нет / папка есть и ПУСТА (снять и перенести — это и есть дефект) / папка НЕ пуста (перенос пофайлово, ничего не затирается, конфликты называются числом) |
| **найденный рядом** | парковка начиналась с `Directory.Delete(testsParked, true)`: если прошлая сборка убита и тесты остались в `Temp`, следующая сборка **уничтожала их навсегда** | сначала САМОЛЕЧЕНИЕ (вернуть остаток на место), потом парковка; если вернуть не удалось — парковка отменяется |

Тесты: `08_Tests\Editor\KvBuildTests.cs`, **6 тестов** — обычный возврат; **папка пересоздана
Unity и пуста**; непустая цель не затирается; возвращать нечего; отчёт называет числа;
**остаток убитой сборки не уничтожается**. В отчёте появились числа, и строка о возврате
попадает в журнал сборки — «тишина вместо ответа» и была причиной, по которой дефект прожил
с §28 по §30 незамеченным.

Живое доказательство: TODO (на пересборке APK №2 в логе обязаны быть строки
`Тесты убраны из сборки APK: … файлов N …` и `тесты возвращены в Assets …`).
